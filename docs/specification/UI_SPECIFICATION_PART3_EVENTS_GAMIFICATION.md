## 1. Events Catalog (Каталог мероприятий)

### 1.1. Цель и Контекст

**Бизнес-задача:** Каталог мероприятий для владельцев питомцев: выставки, спортивные соревнования, образовательные вебинары, тематические встречи. Расширение круга общения и обучение через оффлайн- и онлайн-активность.

**Место в сценарии:** Доступен через навигацию из Home или отдельный раздел "События". Пользователь просматривает доступные мероприятия, фильтрует по типу и дате, регистрируется на интересующие события.

**Ключевые функции:** Просмотр каталога, фильтрация, поиск, регистрация на события.

### 1.2. Элементы Интерфейса и Функциональность

#### 1.2.1. Структура Экрана

**Компонент: Navigation Header**
- Заголовок: "События" (локализованный)
- Кнопка поиска: В правом углу
- Иконка: `search-20`
- Действие: Открытие поиска

**Компонент: Filter Tabs**
- Вкладки:
  - **Все** (по умолчанию)
  - **Выставки**
  - **Спорт**
  - **Вебинары**
  - **Встречи**
- Интерактивность: Переключение между категориями

**Компонент: Date Filter**
- Сегментированный контрол:
  - Сегодня
  - На этой неделе
  - В этом месяце
  - Все
- Действие: Фильтрация по дате

**Компонент: Search Bar**
- Поле поиска: "Поиск событий..."
- Иконка: `search-20`
- Действие: Фильтрация в реальном времени
- Поиск по: Названию, описанию, организатору

**Компонент: Events List**
- Тип: Вертикальный список карточек событий
- Прокрутка: Вертикальный ScrollView
- Pull-to-Refresh: Обновление списка
- Infinite Scroll: Автоматическая подгрузка

**Структура карточки события:**
- **Изображение:** Фото события или обложка
- **Название:** Название события
- **Тип:** Бейдж с типом (выставка/спорт/вебинар/встреча)
- **Дата и время:** Форматированная дата и время
- **Место:** Адрес (для оффлайн) или "Онлайн"
- **Организатор:** Название организатора
- **Статус регистрации:**
  - "Свободных мест: N" (если есть места)
  - "Регистрация закрыта" (если нет мест)
  - "Вы зарегистрированы" (если пользователь зарегистрирован)
- **Краткое описание:** 1-2 строки
- **Действие:** Тап → переход на детальную информацию

#### 1.2.2. Интерактивность

**Тап на карточку события:**
- Переход на детальную информацию о событии
- Действие: `viewModel.showEventDetail(eventId:)`
- Аналитика: `event_detail_opened` с параметром `event_id`

**Тап на фильтр:**
- Обновление списка событий
- Подсветка активного фильтра
- Аналитика: `event_filter_applied`

**Поиск:**
- Ввод текста → фильтрация в реальном времени
- Поиск по названию, описанию, организатору
- Очистка поиска → возврат к полному списку

**Pull-to-Refresh:**
- Потягивание вниз → обновление списка
- Вызов `viewModel.loadEvents()`

#### 1.2.3. Валидация

**Валидация не требуется:**
- Экран информационный, пользовательский ввод только в поиске

### 1.3. Техническая Реализация

#### 1.3.1. Сервисы и API

**API Endpoint: GET /events**
- Метод: `GET`
- Путь: `/events`
- Требует авторизации: Нет (публичный доступ)
- Query параметры:
  - `page`: Номер страницы
  - `limit`: Количество на странице (по умолчанию 20)
  - `type`: Тип события (`exhibition` | `sport` | `webinar` | `meetup`)
  - `startDate`: Начальная дата (опционально)
  - `endDate`: Конечная дата (опционально)
  - `search`: Текст поиска (опционально)
  - `city`: Город (опционально)
- Кэш: `cacheIfValid(300)` (5 минут)
- Retry: `exponential(maxAttempts: 3, initialDelay: 1.0)`

**Ответ при успехе (200 OK):**
```json

    {
      "id": "event_123",
```

- Входные данные: `EventListRequest(filters, pagination)`

  2. Вызов `EventNetworkService.fetchEvents()`
  3. Конвертация DTO в Entities
  4. Возврат массива `Event`

#### 1.3.2. Состояния Экрана

**Состояние: Загрузка**
- Индикатор загрузки
- Placeholder для списка

**Состояние: Успех**
- Список событий отображается
- Карточки заполнены данными
- Применены фильтры (если выбраны)

**Состояние: Пустое**
- Если нет событий → отображается пустое состояние
- Иконка и текст "События не найдены"
- Предложение изменить параметры поиска/фильтры

**Состояние: Ошибка**
- Alert с сообщением об ошибке
- Возможность повторить загрузку

**Состояние: Загрузка следующей страницы**
- Индикатор внизу списка
- Автоматическая подгрузка при прокрутке

#### 1.3.3. Навигация

**Входящие переходы:**
- Из Home (навигация)
- Из Calendar (кнопка "Все события")

**Исходящие переходы:**
- Детальная информация → `.eventDetail(eventId:)`
- Регистрация → `.eventRegistration(eventId:)`

**Методы навигации:**
- Открытие: `coordinator.showEventsCatalog()`
- Детальная информация: `coordinator.showEventDetail(id:)`

#### 1.3.4. Данные

**Event:**
```swift
struct Event: Identifiable, Codable {
    let id: String
    let title: String
    let description: String
    let type: EventType
    let category: EventCategory
    let startDate: Date
    let endDate: Date
    let location: EventLocation
    let organizer: EventOrganizer
    let image: String?
    let capacity: Int
    let registered: Int
    let isRegistered: Bool
    let price: EventPrice
    let tags: [String]
}

enum EventType: String, Codable {
    case exhibition = "exhibition"
    case sport = "sport"
    case webinar = "webinar"
    case meetup = "meetup"
}

enum EventCategory: String, Codable {
    case sport = "sport"
    case education = "education"
    case social = "social"
    case competition = "competition"
}

struct EventLocation: Codable {
    let type: LocationType
    let address: String?
    let coordinates: Coordinates?
    let onlineLink: String?
}

enum LocationType: String, Codable {
    case offline = "offline"
    case online = "online"
    case hybrid = "hybrid"
}

struct EventPrice: Codable {
    let amount: Decimal
    let currency: String
    let isFree: Bool
}
```

#### 1.3.5. Обработка Ошибок

**Типы ошибок:**
- **NetworkError:** Ошибка сети
- **ServerError:** Ошибка сервера

**Отображение ошибок:**
- Alert с понятным сообщением
- Возможность повторить загрузку
- Логирование через `Logger`

#### 1.3.6. Аналитика

**Отслеживаемые события:**
- `screen_view: EventsCatalog` - при появлении экрана
- `event_searched` - поиск событий (параметры: `search_query`)
- `event_filter_applied` - применение фильтра (параметры: `filter_type`, `filter_value`)
- `event_detail_opened` - открытие детальной информации (параметры: `event_id`)

## 2. Event Detail (Детальная информация о событии)

### 2.1. Цель и Контекст

**Бизнес-задача:** Детальная информация о событии с полным описанием, программой, списком участников и возможностью регистрации. Полный контекст для принятия решения об участии.

**Место в сценарии:** Открывается при тапе на карточку события из каталога. Пользователь просматривает детальную информацию, программу, регистрируется на событие.

### 2.2. Элементы Интерфейса и Функциональность

#### 2.2.1. Структура Экрана

**Компонент: Header Image**
- Изображение события (большое, вверху)
- Кнопка "Назад": В левом углу
- Кнопка "Поделиться": В правом углу

**Компонент: Event Info Card**
- Название события
- Тип события (бейдж)
- Дата и время: Форматированная дата с временем
- Место: Адрес или "Онлайн" с ссылкой
- Организатор: Аватар и название (кликабельно)
- Цена: "Бесплатно" или форматированная сумма

**Компонент: Description**
- Полное описание события
- Программа (если есть)
- Многострочный текст с прокруткой

**Компонент: Statistics**
- Карточка со статистикой:
  - Зарегистрировано: N из M
  - Свободных мест: N
  - Прогресс-бар заполненности (опционально)

**Компонент: Participants (Опционально)**
- Заголовок: "Участники"
- Список аватаров участников
- Кнопка "Показать всех" (если участников много)

**Компонент: Action Buttons**
- Кнопка "Зарегистрироваться" (Primary button, если не зарегистрирован)
- Кнопка "Отменить регистрацию" (Secondary button, если зарегистрирован)
- Кнопка "Поделиться" (Text button)

#### 2.2.2. Интерактивность

**Тап на "Зарегистрироваться":**
- Переход на экран регистрации
- Действие: `viewModel.showRegistration(eventId:)`

**Тап на "Отменить регистрацию":**
- Подтверждение отмены
- Отмена регистрации
- Обновление статуса

**Тап на организатора:**
- Переход на профиль организатора (если реализовано)

**Тап на "Поделиться":**
- Системный share sheet
- Копирование ссылки на событие

**Тап на адрес (для оффлайн):**
- Открытие карты с местоположением
- Или переход в приложение карт

### 2.3. Техническая Реализация

#### 2.3.1. Сервисы и API

**API Endpoint: GET /events/{eventId}**
- Метод: `GET`
- Путь: `/events/{eventId}`
- Требует авторизации: Нет

**API Endpoint: GET /events/{eventId}/participants**
- Метод: `GET`
- Путь: `/events/{eventId}/participants`
- Query параметры: `page`, `limit`

**Use Case: FetchEventDetailUseCase**

## 3. Event Registration (Регистрация на событие)

### 3.1. Цель и Контекст

**Бизнес-задача:** Регистрация пользователя на событие с выбором питомца (если применимо), подтверждением участия и оплатой (если требуется). Запись на события прямо в приложении.

**Место в сценарии:** Открывается из детальной информации о событии при нажатии "Зарегистрироваться". Пользователь заполняет форму, выбирает питомца (если нужно), подтверждает регистрацию и оплачивает (если требуется).

### 3.2. Элементы Интерфейса и Функциональность

#### 3.2.1. Структура Экрана

**Компонент: Event Summary**
- Краткая информация о событии:
  - Название
  - Дата и время
  - Место
  - Цена

**Компонент: Registration Form**
- Поля формы:
  - **Выбор питомца:** Выпадающий список (если применимо)
  - **Количество участников:** Число (если можно несколько)
  - **Дополнительная информация:** Многострочное поле (опционально)
  - **Согласие с правилами:** Чекбокс (обязательно)
- Валидация: Все обязательные поля должны быть заполнены

**Компонент: Payment Section (если требуется оплата)**
- Информация о платеже:
  - Сумма к оплате
  - Метод оплаты (выбор)
- Интеграция с Payment Screen

**Компонент: Submit Button**
- Кнопка "Зарегистрироваться" (Primary button)
- Состояния: Активна/Неактивна/Загрузка
- Действие: `viewModel.submitRegistration()`

#### 3.2.2. Интерактивность

**Заполнение формы:**
- Валидация в реальном времени
- Ошибки отображаются под полями
- Автосохранение черновика (опционально)

**Выбор питомца:**
- Тап на выпадающий список
- Выбор из списка питомцев пользователя
- Валидация: Должен быть выбран питомец (если требуется)

**Оплата (если требуется):**
- Интеграция с Payment Screen
- Обработка платежа
- Подтверждение после успешной оплаты

**Отправка регистрации:**
- Валидация всех полей
- Отправка на сервер
- Подтверждение регистрации
- Переход на экран успеха

### 3.3. Техническая Реализация

#### 3.3.1. Сервисы и API

**API Endpoint: POST /events/{eventId}/register**
- Метод: `POST`
- Путь: `/events/{eventId}/register`
- Требует авторизации: Да
- Тело запроса:
```json
{
  "eventId": "event_123",
  "petId": "pet_456",
  "participantCount": 1,
  "additionalInfo": "Дополнительная информация",
  "paymentMethod": "card",
  "agreeToTerms": true
}
```

**Ответ при успехе (201 Created):**
```json
{
  "registrationId": "reg_789",
  "status": "confirmed",
  "event": {
    "id": "event_123",
    "title": "Выставка собак"
  },
  "payment": {
    "required": true,
    "amount": 500.00,
    "currency": "RUB",
    "status": "pending"
  },
  "message": "Регистрация успешно оформлена. Ожидайте подтверждения."
}
```

**Use Case: RegisterForEventUseCase**
- Входные данные: `EventRegistrationInput(eventId, petId, participantCount, additionalInfo)`
- Выходные данные: `NetworkResult<EventRegistration>`
- Действия:
  1. Валидация данных
  2. Проверка доступности мест
  3. Создание регистрации
  4. Обработка платежа (если требуется)
  5. Подтверждение регистрации

## 4. Achievements (Система достижений)

### 4.1. Цель и Контекст

**Бизнес-задача:** Мотивация пользователей через систему достижений и бейджей за активность в приложении. Геймификация для повышения вовлеченности и обучения правильному уходу за питомцами.

**Место в сценарии:** Доступен из Profile экрана через пункт меню "Достижения". Пользователь просматривает свои достижения, прогресс к новым и историю получения.

**Ключевые функции:** Просмотр достижений, прогресс к новым, история получения, сравнение с друзьями.

### 4.2. Элементы Интерфейса и Функциональность

#### 4.2.1. Структура Экрана

**Компонент: Navigation Header**
- Заголовок: "Достижения" (локализованный)
- Кнопка "Статистика": В правом углу (опционально)

**Компонент: User Stats Summary**
- Карточка с общей статистикой:
  - Всего достижений: N из M
  - Уровень: X (если есть уровни)
  - Очки: N (если есть система очков)
- Прогресс-бар общего прогресса

**Компонент: Achievement Categories**
- Вкладки или фильтры:
  - **Все**
  - **Здоровье** (визиты к ветеринару, прививки)
  - **Уход** (груминг, кормление)
  - **Социальные** (публикации, комментарии)
  - **События** (участие в мероприятиях)
  - **Благотворительность** (пожертвования, усыновление)

**Компонент: Achievements Grid**
- Сетка достижений (2-3 колонки)
- Карточки достижений:
  - **Иконка/Бейдж:** Визуальное представление
  - **Название:** Название достижения
  - **Описание:** Условие получения
  - **Статус:**
    - Получено (с датой получения)
    - В процессе (прогресс-бар)
    - Заблокировано (затемненное)
- Тап на достижение → детальная информация

#### 4.2.2. Интерактивность

**Тап на достижение:**
- Открытие детальной информации
- Показ прогресса (если не получено)
- История получения (если получено)

**Фильтрация по категориям:**
- Тап на категорию → обновление списка
- Подсветка активной категории

**Просмотр статистики:**
- Тап на "Статистика" → детальная статистика
- Графики прогресса, сравнение с друзьями

## 5. Leaderboard (Таблица лидеров)

### 5.1. Цель и Контекст

**Бизнес-задача:** Таблица лидеров для соревновательного элемента и мотивации пользователей. Сравнение активности и достижений с другими участниками сообщества.

**Место в сценарии:** Доступен из Achievements экрана или отдельный раздел. Пользователь просматривает рейтинг, свое место и сравнивает с друзьями.

### 5.2. Элементы Интерфейса и Функциональность

#### 5.2.1. Структура Экрана

**Компонент: Navigation Header**
- Заголовок: "Таблица лидеров" (локализованный)
- Кнопка фильтра: В правом углу

**Компонент: Period Selector**
- Сегментированный контрол:
  - Неделя
  - Месяц
  - Год
  - Все время
- Действие: Обновление рейтинга

**Компонент: Category Filter**
- Фильтры:
  - **Общий рейтинг** (по умолчанию)
  - **Здоровье**
  - **Уход**
  - **Социальные**
  - **События**
  - **Благотворительность**

**Компонент: User Position Card**
- Карточка с позицией пользователя:
  - Место: N из M
  - Очки: N
  - Прогресс до следующего места
- Выделение: Акцентный цвет

**Компонент: Leaderboard List**
- Список лидеров (топ 100)
- Карточки участников:
  - **Место:** Номер места (1, 2, 3 с медалями)
  - **Аватар:** Фото пользователя
  - **Имя:** Имя пользователя
  - **Очки:** Количество очков
  - **Прогресс:** Прогресс-бар (опционально)
- Выделение текущего пользователя

#### 5.2.2. Интерактивность

**Тап на участника:**
- Переход на профиль участника (если разрешено)
- Просмотр его достижений

**Изменение периода:**
- Тап на период → обновление рейтинга
- Аналитика: `leaderboard_period_changed`

**Изменение категории:**
- Тап на категорию → обновление рейтинга
- Аналитика: `leaderboard_category_changed`

**Pull-to-Refresh:**
- Обновление рейтинга
- Вызов `viewModel.loadLeaderboard()`

### 5.3. Техническая Реализация

#### 5.3.1. Сервисы и API

**API Endpoint: GET /gamification/leaderboard**
- Метод: `GET`
- Путь: `/gamification/leaderboard`
- Требует авторизации: Да
- Query параметры:
  - `period`: Период (`week` | `month` | `year` | `all_time`)
  - `category`: Категория (опционально)
  - `page`: Номер страницы
  - `limit`: Количество на странице (по умолчанию 50)

**Ответ при успехе (200 OK):**

```json
  },

    "page": 1,
    "limit": 50,
    "total": 1000
  }
```

**Use Case: FetchLeaderboardUseCase**
- Входные данные: `LeaderboardRequest(period, category, pagination)`
- Выходные данные: `NetworkResult<Leaderboard>`
