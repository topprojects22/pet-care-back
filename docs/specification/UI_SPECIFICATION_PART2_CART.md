## 1. Cart

### 1.1. Цель и Контекст

**Бизнес-задача:** Экран корзины/магазина для поиска и просмотра магазинов, сервисов и товаров для питомцев. Marketplace для бронирования услуг и покупки товаров.

**Место в сценарии:** Доступен через таб-бар (третий таб) или из других мест приложения. Является центральным экраном для поиска и бронирования услуг (ветеринар, груминг, передержка).

**Ключевые функции:** Поиск магазинов/сервисов, фильтрация, просмотр списка, переход к детальной информации.

### 1.2. Элементы Интерфейса и Функциональность

#### 1.2.1. Структура Экрана

**Компонент: SearchStoreWidget**
- Тип: Виджет поиска магазинов
- Привязка: `$viewModel.searchStore`
- Действие при вводе: `viewModel.inputStoreSearch(value:)`
- Действие фильтра: `viewModel.inputShowFilter(value: true)`
- Функции:
  - Поиск по названию магазина/сервиса
  - Кнопка фильтрации
  - Поле ввода с иконкой поиска

**Компонент: StoreListWidget**
- Тип: Список магазинов/сервисов
- Данные: `viewModel.stores` (массив `Store`)
- Отображение: Карточки магазинов
- Действие: Тап на карточку → переход к детальной информации
- Прокрутка: Вертикальный ScrollView

**Модальное окно фильтров:**
- Тип: Sheet
- Привязка: `$viewModel.showFilterModal`
- Содержимое: Фильтры для поиска (TODO - не реализовано)
- Действие: Применение фильтров к списку

#### 1.2.2. Интерактивность

**Поиск:**
- Ввод текста → обновление `searchStore`
- Автоматический поиск или по кнопке (зависит от реализации)
- Аналитика: `store_search` с параметром `query`

**Фильтрация:**
- Тап на кнопку фильтра → открытие модального окна
- Применение фильтров → обновление списка
- Аналитика: `filter_toggled` с параметром `is_open`

**Тап на карточку магазина:**
- Переход к детальной информации магазина/сервиса
- Или переход к профилю ветеринара/грумера

**Pull-to-Refresh (опционально):**
- Потягивание вниз → обновление списка
- Вызов `viewModel.loadStores()`

#### 1.2.3. Валидация

**Валидация не требуется:**
- Экран поиска и списка, пользовательский ввод только в поиске
- Поиск работает с любым текстом

### 1.3. Техническая Реализация

#### 1.3.1. Сервисы и API

**API Endpoint: GET /stores**
- Метод: `GET`
- Путь: `/stores`
- Требует авторизации: Да (`requiresAuth: true`)
- Query параметры:
  - `search`: Текст поиска (опционально)
  - `filter`: Параметры фильтрации (опционально)
- Кэш: `cacheIfValid(300)` (5 минут)
- Retry: `exponential(maxAttempts: 3, initialDelay: 1.0)`

**Ответ при успехе (200 OK):**
```json
{
  "data": [
    {
      "id": 1,
      "name": "ВетКлиника",
      "type": "veterinary",
      "rating": 4.5,
      "address": "Москва, ул. Примерная, д. 1",
      "image": "url_to_image",
      "services": ["Консультация", "Вакцинация"]
    }
  ]
}
```

**Use Case: FetchStoreListUseCase**
- Входные данные: `StoreListRequest(search: String?, filters: StoreFilters?)`
- Выходные данные: `NetworkResult<[Store]>`
- Действия:
  1. Создание `NetworkRequest` с query параметрами
  2. Вызов `CartNetworkService.fetchStores()`
  3. Конвертация DTO в Entities
  4. Возврат массива `Store`

**Состояние: Загрузка**

#### 1.3.3. Навигация

**Исходящие переходы:**
- Детальная информация магазина → экран профиля (Vet Profile или аналогичный)
- Бронирование услуги → экран бронирования (TODO)

**Входящие переходы:**
- Из таб-бара (третий таб)
- Из других мест приложения

**Методы навигации:**
- `coordinator.showVetProfile(for: vetId)` - переход на профиль ветеринара
- `coordinator.showGroomingProfile(for: id)` - переход на профиль грумера (если реализовано)

#### 1.3.4. Данные

**Модель Store:**
```swift
struct Store: Identifiable, Codable {
    let id: Int
    let name: String
    let type: StoreType  // .veterinary, .grooming, .boarding, .shop
    let rating: Double?
    let address: String
    let image: String?
    let services: [String]?
    let phone: String?
    let website: String?
}
```

**Состояние ViewModel:**
- `stores: [Store]` - список магазинов/сервисов
- `searchStore: String` - текст поиска
- `showFilterModal: Bool` - флаг модального окна фильтров

**Фильтры (TODO):**

- Местоположение

#### 1.3.5. Обработка Ошибок

**Типы ошибок:**
- **Неавторизован (401):** Автоматический logout
- **Сервер (500):** Общая ошибка сервера
- **Сеть:** Ошибка подключения

**Стратегия обработки:**
- Ошибки логируются с контекстом `["action": "load_stores"]`
- Пользователь может повторить загрузку
- Использование кэша при ошибках сети

#### 1.3.6. Аналитика

**Отслеживаемые события:**
- `screen_view: Cart` - при появлении экрана
- `stores_loaded` - при успешной загрузке (параметры: `count`)
- `store_search` - при поиске (параметры: `query`)
- `filter_toggled` - при открытии/закрытии фильтров (параметры: `is_open`)
- `store_selected` - при выборе магазина (параметры: `store_id`, `store_type`)
