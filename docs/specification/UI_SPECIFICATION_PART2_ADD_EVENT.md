## 1. Add Event

### 1.1. Цель и Контекст

**Бизнес-задача:** Создание и редактирование событий в календаре питомца: прививки, визиты к ветеринару, обработки, прием лекарств. Форма для ввода всех необходимых данных о событии.

**Место в сценарии:** Отображается как модальное окно из Calendar (кнопка "Добавить" или иконка редактирования). После сохранения событие добавляется в календарь и отображается на выбранной дате.

**Ключевые функции:** Ввод названия, описания, выбор даты и времени, валидация данных.

### 1.2. Элементы Интерфейса и Функциональность

#### 1.2.1. Структура Экрана

**Компонент: NavigationView (Header)**
- Заголовок: 
  - "Новое событие" (если `eventToEdit == nil`)
  - "Редактировать событие" (если `eventToEdit != nil`)
- Кнопка "Отмена": В toolbar слева
  - Действие: `dismiss()` (закрытие модального окна)

**Секция "Основная информация":**
- Заголовок секции: "Основная информация" (18pt, semibold)
- Поле "Название события":
  - Компонент: `TextFieldUI`
  - Placeholder: "Название события"
  - Иконка: `text.alignleft` (системная)
  - Привязка: `$title`
  - Ошибка: `titleError`
  - Конфигурация: Стандартная
  - Валидация: Обязательное поле
- Поле "Описание":
  - Компонент: `TextAreaUI`
  - Placeholder: "Описание (необязательно)"
  - Привязка: `$description`
  - Минимальная высота: 100 points
  - Максимальная длина: 500 символов
- Отступы: Горизонтальные 20 points, верхний 20 points

**Секция "Дата и время":**
- Заголовок секции: "Дата и время" (18pt, semibold)
- Поле "Дата события":
  - Компонент: `DatePickerUI`
  - Заголовок: "Дата события"
  - Привязка: `$eventDate`
  - Иконка: `calendar` (системная)
  - Конфигурация:
    - Mode: `.date`
    - MaxDate: Не ограничена
  - Действие при изменении: Обновление времени при смене даты
- Поля времени (в HStack):
  - **Время начала:**
    - Компонент: `TimePickerUI`
    - Заголовок: "Время начала"
    - Привязка: `$startTime`
    - Иконка: `clock.fill` (системная)
    - Действие при изменении: Проверка, что начало не позже окончания
  - **Время окончания:**
    - Компонент: `TimePickerUI`
    - Заголовок: "Время окончания"
    - Привязка: `$endTime`
    - Иконка: `clock.fill` (системная)
    - Действие при изменении: Проверка, что окончание не раньше начала
- Отступы: Горизонтальные 20 points

**Кнопка "Создать событие" / "Сохранить изменения":**
- Компонент: `ButtonUI`
- Стиль: Primary button, размер large
- Текст:
  - "Создать событие" (если `eventToEdit == nil`)
  - "Сохранить изменения" (если `eventToEdit != nil`)
- Действие: `saveEvent()`
- Отступы: Горизонтальные 20 points, верхний 8 points, нижний 40 points

#### 1.2.2. Интерактивность

**Ввод названия:**
- Реакция на изменение: Очистка ошибки при вводе
- Валидация: При сохранении проверка на пустое поле

**Ввод описания:**
- Многострочный ввод
- Ограничение: Максимум 500 символов
- Счетчик символов (если реализовано)

**Выбор даты:**
- Тап на поле → открытие DatePicker
- При изменении даты: Автоматическое обновление времени (сохранение часов и минут)

**Выбор времени начала:**
- Тап на поле → открытие TimePicker
- При изменении: Проверка, что `startTime < endTime`
- Если нарушено: Автоматическое увеличение `endTime` на 1 час

**Выбор времени окончания:**
- Тап на поле → открытие TimePicker
- При изменении: Проверка, что `endTime > startTime`
- Если нарушено: Автоматическое уменьшение `startTime` на 1 час

**Тап на кнопку "Создать/Сохранить":**
- Валидация всех полей
- Если валидно: Создание/обновление события
- Если невалидно: Отображение ошибок

**Тап на "Отмена":**
- Закрытие модального окна без сохранения
- Данные не сохраняются

#### 1.2.3. Валидация Данных

**Название события:**
- Обязательное поле
- Не может быть пустым (после trim)
- Сообщение об ошибке: "Название события обязательно"

**Описание:**
- Необязательное поле
- Максимальная длина: 500 символов
- Валидация не требуется

**Дата:**
- Может быть любой (включая будущие даты)
- Валидация не требуется

**Время:**
- Время начала должно быть раньше времени окончания
- Автоматическая корректировка при нарушении
- Валидация не требуется (автоматическая проверка)

**Валидация на клиенте:**
- Проверка названия на пустое поле
- Проверка времени (начало < окончание)

#### 1.3.3. Логика Объединения Даты и Времени

**Алгоритм сохранения:**
```swift
// Извлечение компонентов даты
let dateComponents = calendar.dateComponents([.year, .month, .day], from: eventDate)
let startTimeComponents = calendar.dateComponents([.hour, .minute], from: startTime)
let endTimeComponents = calendar.dateComponents([.hour, .minute], from: endTime)

// Объединение даты и времени начала
let finalStartTime = calendar.date(
    bySettingHour: startTimeComponents.hour ?? 0,
    minute: startTimeComponents.minute ?? 0,
    second: 0,
    of: calendar.date(from: dateComponents) ?? eventDate
)

// Объединение даты и времени окончания
let finalEndTime = calendar.date(
    bySettingHour: endTimeComponents.hour ?? 0,
    minute: endTimeComponents.minute ?? 0,
    second: 0,
    of: calendar.date(from: dateComponents) ?? eventDate
)
```

**Проверка времени:**
- При изменении `startTime`: Если `startTime >= endTime`, увеличить `endTime` на 1 час
- При изменении `endTime`: Если `endTime <= startTime`, уменьшить `startTime` на 1 час

**Типы ошибок:**

**Отображение ошибок:**
- Ошибки валидации: Под соответствующими полями

**Отслеживаемые события:**

- `calendar_add_event_opened` - при открытии формы создания
- `calendar_edit_event_opened` - при открытии формы редактирования (параметры: `event_id`)
