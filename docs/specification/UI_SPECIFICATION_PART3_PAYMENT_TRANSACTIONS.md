## 1. Payment Screen

### 1.1. Цель и Контекст

**Бизнес-задача:** Обеспечение безопасной и удобной оплаты услуг через встроенную систему платежей. Поддержка множественных методов оплаты и прозрачное отображение деталей транзакции.

**Место в сценарии:** Отображается как модальный экран (sheet) при необходимости оплаты услуг:
- Бронирование ветеринарных услуг
- Оплата услуг грумера
- Бронирование передержки
- Благотворительные пожертвования
- Покупка подписки

**Ключевые функции:** Выбор метода оплаты, безопасная обработка платежа, подтверждение транзакции.

### 1.2. Элементы Интерфейса и Функциональность

#### 1.2.1. Структура Экрана

**Компонент: Navigation Header**
- Заголовок: "Оплата" (локализованный)
- Кнопка "Отмена": В левом углу toolbar
- Действие: `viewModel.cancelPayment()` → закрытие экрана

**Компонент: Payment Info Section**
- Тип: Карточка с информацией о платеже
- Стиль: Закругленные углы, серый фон
- Содержимое:
  - **Услуга:** Описание услуги (`session.description`)
  - **Сумма:** Форматированная сумма с валютой
  - **Статус:** Бейдж со статусом платежа
- Отступы: 24 points между секциями

**Компонент: Payment Method Section**
- Тип: Список методов оплаты
- Стиль: Карточка с выбором
- Содержимое: Список доступных методов оплаты
- Интерактивность: Выбор метода тапом

**Компонент: Pay Button**
- Тип: Primary button
- Текст: "Оплатить [сумма] [валюта]"
- Состояния:
  - Активна: Когда выбран метод оплаты и сессия валидна
  - Неактивна: Серый цвет, disabled
- Действие: `viewModel.startPayment()`

#### 1.2.2. Методы Оплаты

**Доступные методы:**
- **Apple Pay:** Системная интеграция Apple Pay
- **Банковская карта:** Стандартная оплата картой
- **Stripe:** Через Stripe платежную систему
- **CloudPayments:** Через CloudPayments
- **Сбербанк:** Прямая интеграция со Сбербанком
- **Revenue Cat:** Для подписок

**Отображение метода:**
- Иконка метода (системная или кастомная)
- Название метода
- Индикатор выбора (checkmark при выборе)
- Подсветка выбранного метода

#### 1.2.3. Интерактивность

**Выбор метода оплаты:**
- Тап на метод → `viewModel.selectPaymentMethod(method)`
- Визуальная обратная связь: Подсветка выбранного
- Аналитика: `payment_method_selected` с параметром `method`

**Начало оплаты:**
- Тап на кнопку "Оплатить"
- Валидация сессии
- Запуск процесса оплаты через выбранный процессор
- Отображение индикатора загрузки

**Отмена оплаты:**
- Тап на "Отмена" → закрытие экрана
- Аналитика: `payment_cancelled`

#### 1.2.4. Состояния Платежа

**Статусы платежа:**
- `pending` - Ожидает оплаты (оранжевый)
- `processing` - Обрабатывается (оранжевый)
- `success` - Успешно (зеленый)
- `failed` - Ошибка (красный)
- `cancelled` - Отменен (серый)
- `refunded` - Возврат (синий)

**Визуализация статуса:**
- Цветной бейдж с текстом статуса
- Закругленные углы, padding

#### 1.2.5. Валидация

**Валидация сессии:**
- Проверка валидности платежной сессии
- Проверка доступности метода оплаты
- Проверка суммы (должна быть > 0)

**Валидация метода:**
- Проверка доступности процессора
- Проверка поддержки метода для данного типа услуги

### 1.3. Техническая Реализация

#### 1.3.1. Сервисы и API

**API Endpoint: POST /payment/session**
- Метод: `POST`
- Путь: `/payment/session`
- Требует авторизации: Да (`requiresAuth: true`)
- Тело запроса:
```json
{
  "serviceId": "string",
  "orderId": "string",
  "serviceType": "veterinary|grooming|boarding|charity|subscription",
  "metadata": {
    "key": "value"
  }
}
```

**Ответ при успехе (200 OK):**
```json
{
  "id": "session_123",
  "amount": 1500.00,
  "currency": "RUB",
  "description": "Консультация ветеринара",
  "status": "pending",
  "expiresAt": "2025-01-20T12:00:00Z"
}
```

**Use Case: CreatePaymentSessionUseCase**
- Входные данные: `CreatePaymentSessionInput(serviceId, orderId, metadata)`
- Выходные данные: `PaymentSession`
- Действия:
  1. Создание `NetworkRequest`
  2. Вызов `NetworkService.request()`
  3. Конвертация DTO в `PaymentSession`
  4. Возврат сессии

**Use Case: ProcessPaymentUseCase**
- Входные данные: `ProcessPaymentInput(session, paymentMethod)`
- Выходные данные: `PaymentResult`
- Действия:
  1. Выбор соответствующего `PaymentProcessor`
  2. Обработка платежа через процессор
  3. Получение результата транзакции
  4. Возврат `PaymentResult`

**Use Case: ConfirmPaymentUseCase**
- Входные данные: `ConfirmPaymentInput(session, result)`
- Выходные данные: `Void`
- Действия:
  1. Отправка подтверждения на сервер
  2. Обновление статуса заказа
  3. Логирование транзакции

#### 1.3.2. Состояния Экрана

**Состояние: Загрузка**
- Индикатор загрузки (ProgressView)
- Масштаб: 1.5x
- Показывается при загрузке сессии

**Состояние: Отображение формы**
- Информация о платеже отображается
- Методы оплаты доступны для выбора
- Кнопка оплаты активна/неактивна в зависимости от выбора

**Состояние: Обработка платежа**
- Индикатор загрузки на кнопке
- Все элементы неактивны
- Системный диалог платежа (если требуется)

**Состояние: Успех**
- Alert "Оплата успешна"
- Отображение ID транзакции
- Автоматическое закрытие после подтверждения

**Состояние: Ошибка**
- Alert "Ошибка оплаты"
- Отображение сообщения об ошибке
- Возможность повторить попытку

#### 1.3.3. Навигация

**Входящие переходы:**
- Из Vet Profile (бронирование услуги)
- Из Cart (оплата корзины)
- Из Charity (пожертвование)
- Из Subscription (покупка подписки)

**Исходящие переходы:**
- Успешная оплата → закрытие экрана → возврат на предыдущий экран
- Отмена → закрытие экрана

**Методы навигации:**
- Открытие: `coordinator.showPayment(serviceType, serviceId, orderId, metadata)`
- Закрытие: `coordinator.goBack()` или `dismiss()`

#### 1.3.4. Данные

**PaymentSession:**
```swift
struct PaymentSession: Codable {
    let id: String
    let amount: Decimal
    let currency: String
    let description: String
    let status: PaymentStatus
    let expiresAt: Date?
    var canBePaid: Bool {
        status == .pending && (expiresAt == nil || expiresAt! > Date())
    }
}
```

**PaymentResult:**
```swift
struct PaymentResult {
    let isSuccess: Bool
    let transactionId: String?
    let errorMessage: String?
    let metadata: [String: String]?
}
```

**PaymentMethodType:**
```swift
enum PaymentMethodType: String, CaseIterable {
    case applePay = "apple_pay"
    case card = "card"
    case stripe = "stripe"
    case cloudPayments = "cloud_payments"
    case sberbank = "sberbank"
    case revenuecat = "revenuecat"
}
```

#### 1.3.5. Обработка Ошибок

**Типы ошибок:**
- **InvalidSession:** Сессия невалидна или истекла
- **PaymentProcessorUnavailable:** Процессор недоступен
- **PaymentFailed:** Ошибка обработки платежа
- **NetworkError:** Ошибка сети

**Отображение ошибок:**
- Alert с понятным сообщением
- Логирование через `Logger`
- Возможность повторить попытку

#### 1.3.6. Аналитика

**Отслеживаемые события:**
- `screen_view: Payment` - при появлении экрана
- `payment_session_created` - создание сессии (параметры: `session_id`, `order_id`, `amount`)
- `payment_method_selected` - выбор метода (параметры: `method`)
- `payment_started` - начало оплаты (параметры: `session_id`, `method`)
- `payment_success` - успешная оплата (параметры: `session_id`, `transaction_id`)
- `payment_failed` - ошибка оплаты (параметры: `session_id`, `error`)
- `payment_cancelled` - отмена оплаты (параметры: `session_id`)

## 2. Transaction History

### 2.1. Цель и Контекст

**Бизнес-задача:** Предоставление пользователю полной истории всех финансовых транзакций с возможностью фильтрации, поиска и детального просмотра. Обеспечение прозрачности всех платежей, связанных с питомцем.

**Место в сценарии:** Доступен из Profile экрана через пункт меню "История транзакций" или "Финансовый хаб". Пользователь может просматривать все свои платежи, фильтровать по категориям и датам, экспортировать данные.

**Ключевые функции:** Просмотр истории, фильтрация, поиск, детальный просмотр транзакции, экспорт данных.

### 2.2. Элементы Интерфейса и Функциональность

#### 2.2.1. Структура Экрана

**Компонент: Navigation Header**
- Заголовок: "История транзакций" (локализованный)
- Кнопка фильтра: В правом углу toolbar
- Иконка: `filter_20`
- Действие: Открытие фильтров

**Компонент: Summary Card (Опционально)**
- Тип: Карточка с общей статистикой
- Содержимое:
  - **Общая сумма:** Всего потрачено за период
  - **Количество транзакций:** Всего операций
  - **Период:** Выбранный период (месяц/год)
- Стиль: Закругленная карточка, акцентный цвет

**Компонент: Filter Bar**
- Тип: Горизонтальный список фильтров
- Фильтры:
  - **Все** (по умолчанию)
  - **Ветеринарные услуги**
  - **Груминг**
  - **Передержка**
  - **Благотворительность**
  - **Подписка**
- Интерактивность: Тап на фильтр → обновление списка

**Компонент: Search Bar**
- Тип: Поле поиска
- Placeholder: "Поиск по описанию, сумме..."
- Иконка: `search-20`
- Действие: Фильтрация списка в реальном времени

**Компонент: Transaction List**
- Тип: Вертикальный список транзакций
- Группировка: По датам (сегодня, вчера, на этой неделе, в этом месяце, раньше)
- Прокрутка: Вертикальный ScrollView
- Pull-to-Refresh: Обновление списка

**Структура карточки транзакции:**
- **Дата и время:** Форматированная дата
- **Описание:** Название услуги/операции
- **Категория:** Бейдж с категорией
- **Сумма:** Форматированная сумма с валютой
- **Статус:** Бейдж со статусом
- **Иконка:** Иконка категории (опционально)

#### 2.2.2. Интерактивность

**Тап на транзакцию:**
- Переход на детальный экран транзакции
- Отображение полной информации:
  - Детали услуги
  - Метод оплаты
  - ID транзакции
  - Статус
  - Дата и время
  - Чек (если доступен)

**Тап на фильтр:**
- Обновление списка транзакций
- Подсветка активного фильтра
- Аналитика: `transaction_filter_applied`

**Поиск:**
- Ввод текста → фильтрация в реальном времени
- Поиск по описанию, сумме, категории
- Очистка поиска → возврат к полному списку

**Pull-to-Refresh:**
- Потягивание вниз → обновление списка
- Вызов `viewModel.loadTransactions()`

**Swipe действия (опционально):**
- Swipe влево → экспорт транзакции
- Swipe вправо → повтор платежа (если применимо)

#### 2.2.3. Фильтрация и Сортировка

**Фильтры:**
- **По категории:** Ветеринар, груминг, передержка, благотворительность, подписка
- **По статусу:** Все, успешные, неуспешные, ожидающие
- **По периоду:** Сегодня, неделя, месяц, год, все время
- **По сумме:** Диапазон сумм

**Сортировка:**
- По дате (новые сначала / старые сначала)
- По сумме (больше / меньше)
- По категории (алфавитно)

**Применение фильтров:**
- Множественный выбор фильтров
- Кнопка "Применить" или автоматическое применение
- Кнопка "Сбросить" для очистки фильтров

#### 2.2.4. Валидация

**Валидация не требуется:**
- Экран информационный, пользовательский ввод только в поиске и фильтрах

### 2.3. Техническая Реализация

#### 2.3.1. Сервисы и API

**API Endpoint: GET /payment/transactions**
- Метод: `GET`
- Путь: `/payment/transactions`
- Требует авторизации: Да (`requiresAuth: true`)
- Query параметры:
  - `page`: Номер страницы (опционально)
  - `limit`: Количество на странице (опционально, по умолчанию 20)
  - `category`: Категория (опционально)
  - `status`: Статус (опционально)
  - `startDate`: Начальная дата (опционально)
  - `endDate`: Конечная дата (опционально)
  - `search`: Текст поиска (опционально)
- Кэш: `cacheIfValid(300)` (5 минут)
- Retry: `exponential(maxAttempts: 3, initialDelay: 1.0)`

**Ответ при успехе (200 OK):**
```json
{
  "data": [
    {
      "id": "txn_123",
      "orderId": "order_456",
      "serviceType": "veterinary",
      "description": "Консультация ветеринара",
      "amount": 1500.00,
      "currency": "RUB",
      "status": "success",
      "paymentMethod": "card",
      "createdAt": "2025-01-15T10:30:00Z",
      "completedAt": "2025-01-15T10:31:00Z",
      "metadata": {
        "clinicId": "123",
        "petId": "456"
      }
    }
  ],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 150,
    "hasMore": true
  }
}
```

**Use Case: FetchTransactionsUseCase**
- Входные данные: `TransactionListRequest(filters, pagination)`
- Выходные данные: `NetworkResult<[Transaction]>`
- Действия:
  1. Создание `NetworkRequest` с query параметрами
  2. Вызов `PaymentNetworkService.fetchTransactions()`
  3. Конвертация DTO в Entities
  4. Возврат массива `Transaction`

#### 2.3.4. Данные

**Transaction:**
```swift
struct Transaction: Identifiable, Codable {
    let id: String
    let orderId: String
    let serviceType: ServiceType
    let description: String
    let amount: Decimal
    let currency: String
    let status: PaymentStatus
    let paymentMethod: PaymentMethodType
    let createdAt: Date
    let completedAt: Date?
    let metadata: [String: String]?
    
    var category: TransactionCategory {
        switch serviceType {
        case .veterinary: return .veterinary
        case .grooming: return .grooming
        case .boarding: return .boarding
        case .charity: return .charity
        case .subscription: return .subscription
        }
    }
}
```

**TransactionCategory:**
```swift
enum TransactionCategory: String, CaseIterable {
    case veterinary = "veterinary"
    case grooming = "grooming"
    case boarding = "boarding"
    case charity = "charity"
    case subscription = "subscription"
    
    var displayName: String {
        switch self {
        case .veterinary: return "Ветеринарные услуги"
        case .grooming: return "Груминг"
        case .boarding: return "Передержка"
        case .charity: return "Благотворительность"
        case .subscription: return "Подписка"
        }
    }
}
```
