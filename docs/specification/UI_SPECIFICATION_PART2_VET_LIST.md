## 1. Vet List

### 1.1. Цель и Контекст

**Бизнес-задача:** Список ветеринарных клиник с возможностью поиска, фильтрации и выбора. Центральный экран для поиска ветеринарных услуг и записи на приём.

**Место в сценарии:** Доступен через навигацию из Home или других мест приложения. Является отправной точкой для поиска ветеринарных услуг. После выбора клиники пользователь переходит на Vet Profile.

**Ключевые функции:** Поиск клиник, фильтрация, просмотр списка, переход к профилю клиники.

### 1.2. Элементы Интерфейса и Функциональность

#### 1.2.1. Структура Экрана

**Компонент: TitleTopListWidget (Header)**
- Тип: Заголовок списка
- Содержимое: Заголовок "Ветеринарные клиники" (предположительно)
- Отступы: Стандартные отступы

**Компонент: ItemListWidget**
- Тип: Список ветеринарных клиник
- Действие: `onVetSelected: { vetId in ... }`
- Функция: Отображение карточек клиник
- Прокрутка: Вертикальный ScrollView
- Отступы: Вертикальные padding

**Структура карточки клиники (предположительно):**
- Название клиники
- Рейтинг и количество отзывов
- Адрес
- Изображение (опционально)
- Основные услуги (опционально)
- Действие: Тап → переход на Vet Profile

#### 1.2.2. Интерактивность

**Тап на карточку клиники:**
- Переход на экран Vet Profile
- Действие: `viewModel.goToVetProfile(vetId: vetId)`
- Аналитика: `vet_profile_opened` с параметром `vet_id`

**Поиск (если реализовано):**
- Ввод текста → фильтрация списка
- Поиск по названию, адресу, услугам

**Фильтрация (если реализовано):**
- Фильтры по рейтингу, местоположению, услугам
- Применение фильтров → обновление списка

**Pull-to-Refresh (если реализовано):**
- Потягивание вниз → обновление списка
- Вызов `viewModel.loadVets()` (если реализовано)

#### 1.2.3. Валидация

**Валидация не требуется:**
- Экран информационный, пользовательский ввод только в поиске (если реализовано)

### 1.3. Техническая Реализация

#### 1.3.1. Сервисы и API

**API Endpoint: GET /medical/clinics**
- Метод: `GET`
- Путь: `/medical/clinics`
- Требует авторизации: Да (`requiresAuth: true`)
- Query параметры:
  - `search`: Текст поиска (опционально)
  - `rating`: Минимальный рейтинг (опционально)
  - `location`: Местоположение (опционально)
- Кэш: `cacheIfValid(600)` (10 минут)
- Retry: `exponential(maxAttempts: 3, initialDelay: 1.0)`

**Ответ при успехе (200 OK):**
```json
{
  "data": [
    {
      "id": 1,
      "name": "ВетКлиника",
      "rating": 4.5,
      "reviewCount": 120,
      "address": "Москва, ул. Примерная, д. 1",
      "phone": "+79001234567",
      "image": "url_to_image",
      "services": ["Консультация", "Вакцинация"]
    }
  ]
}
```

#### 1.3.4. Данные

**Модель Vet (используется из Vet Profile):**
```swift
struct Vet: Identifiable, Codable {
    let id: Int

    let rating: Double
    let reviewCount: Int

    let image: String?
    let services: [String]?
}
```

**Состояние ViewModel:**
- В текущей реализации состояние не определено явно

**Репозиторий:**
- `VetListRepository` - базовый репозиторий для работы с данными клиник
- В текущей реализации не интегрирован с API

#### 1.3.5. Обработка Ошибок

**Типы ошибок:**
- **Неавторизован (401):** Автоматический logout
- **Сервер (500):** Общая ошибка сервера
- **Сеть:** Ошибка подключения

**Стратегия обработки:**
- Ошибки логируются через `handleError()`
- Пользователь может повторить загрузку
- Использование кэша при ошибках сети

#### 1.3.6. Аналитика

**Отслеживаемые события:**
- `screen_view: VetList` - при появлении экрана
- `vet_profile_opened` - при открытии профиля клиники (параметры: `vet_id`)
- `vet_list_searched` - при поиске (параметры: `query`) - если реализовано
- `vet_list_filtered` - при применении фильтров (параметры: `filters`) - если реализовано
