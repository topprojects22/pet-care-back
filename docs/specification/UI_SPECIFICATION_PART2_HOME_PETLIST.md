## 1. Home Screen

### 1.1. Цель и Контекст

**Бизнес-задача:** Главный экран приложения, предоставляющий быстрый доступ к ключевой информации: событиям календаря, статистике питомцев, и навигации по основным разделам. Центральный хаб для ежедневного использования приложения.

**Место в сценарии:** Отображается после успешной авторизации и подписки. Является основным экраном в таб-баре приложения (первый таб). Пользователь возвращается на этот экран для просмотра актуальных событий и быстрого доступа к функциям.

**Частота использования:** Самый часто используемый экран приложения.

### 1.2. Элементы Интерфейса и Функциональность

#### 1.2.1. Структура Экрана

**Компонент: TitleTopWidget (Header)**
- Позиция: Верх экрана, фиксированный
- Элементы:
  - **Правая иконка:** Уведомления (`bell-20`)
    - Badge: Красный индикатор с числом непрочитанных (например, "3")
    - Действие: Переход на экран уведомлений
  - **Аватар пользователя:** Изображение `avatar`
    - Позиция: Справа
    - Действие: Переход на профиль пользователя
- Отступы: Горизонтальные 20 points, верхний отступ стандартный

**Компонент: CarouselUI (Карусель карточек)**
- Тип: Горизонтальная прокручиваемая карусель
- Количество карточек: 3 (динамически может изменяться)
- Анимация: Плавный swipe между карточками
- Индикатор: Точки внизу (PageControl)

**Содержимое карточек:**
- **Карточка 1:**
  - Компонент: `TopCardUI`
  - Заголовок: "Daily score"
  - Описание: "tasks completed"
  - Метка: "4/7" (выполнено/всего)
  - Статус: `isActive: false`
  - Контент: `Rectangle()` (заглушка для графика)

- **Карточка 2:**
  - Аналогичная структура
  - Контент: `Rectangle().frame(width: 100, height: 100)`

- **Карточка 3:**
  - Аналогичная структура
  - Контент: `Rectangle().frame(width: 100, height: 100)`

**Компонент: TitleListWidget**
- Заголовок: "All events" (локализованный)
- Позиция: Под каруселью
- Действие: Тап на заголовок → переход на экран Calendar
- Стиль: Заголовок с кнопкой "Смотреть все" (опционально)

**Компонент: TimelineUI**
- Тип: Вертикальный список событий
- Конфигурация: `.compact` (компактный вид)
- Данные: Массив `TimelineEvent` (8 событий в примере)
- Прокрутка: Вертикальный ScrollView
- Отступы: Горизонтальные 20 points, нижний отступ 55 points

#### 1.2.2. Интерактивность

**Swipe по карусели:**
- Горизонтальный swipe влево/вправо → переход между карточками
- Анимация: Плавный переход с эффектом "страницы"

**Тап на иконку уведомлений:**
- Переход на экран `.notifications`
- Аналитика: `navigate_to_notifications`

**Тап на аватар:**
- Переход на экран `.profile(userID: "1")`
- Аналитика: `navigate_to_profile`

**Тап на "All events":**
- Переход на экран `.calendar`
- Аналитика: `navigate_to_calendar`

**Тап на событие в Timeline:**
- Переход на детальную информацию о событии (если реализовано)
- Или переход на экран Calendar с выделением события

#### 1.2.3. Валидация

**Валидация не требуется:**
- Экран информационный, пользовательский ввод отсутствует
- Все действия являются навигационными

### 1.3. Техническая Реализация

#### 1.3.1. Сервисы и API

**API Endpoint: GET /user/profile**
- Метод: `GET`
- Путь: `/user/profile`
- Требует авторизации: Да (`requiresAuth: true`)
- Кэш: `cacheIfValid(300)` (5 минут)
- Retry: `exponential(maxAttempts: 3, initialDelay: 1.0)`

**Ответ при успехе (200 OK):**
```json
{
  "data": {
    "id": 1,
    "name": "Marco Rivera",
    "email": "user@example.com",
    "avatar": "url_to_avatar"
  }
}
```

**Use Case: FetchProfileUseCase**
- Входные данные: `Void`
- Выходные данные: `NetworkResult<Profile>`
- Действия:
  1. Вызов `ProfileNetworkService.fetchProfile()`
  2. Получение данных профиля
  3. Обновление `userName` в ViewModel

**События календаря:**
- Источник: Локальные данные или API (если реализовано)
- В примере: `TimelineEvent.sampleEvents(count: 8)` - заглушка
- В продакшене: Загрузка из `CalendarRepository` или `NotificationRepository`

#### 1.3.2. Состояния Экрана

**Состояние: Загрузка**
- Индикатор загрузки (если требуется)
- Карусель и события отображаются с placeholder данными
- Аватар и имя пользователя загружаются асинхронно

**Состояние: Успех**
- Все данные загружены
- Имя пользователя отображается (из профиля)
- Карусель с актуальными данными
- Список событий отображается

**Состояние: Ошибка**
- Ошибка загрузки профиля: Логируется, но не блокирует экран
- Ошибка загрузки событий: Отображается пустое состояние или кэшированные данные
- Пользователь может продолжать использовать экран

**Состояние: Пустое (события)**
- Если нет событий: Отображается сообщение "Нет событий"
- Предложение добавить событие или перейти в календарь

#### 1.3.3. Навигация

**Исходящие переходы:**
- Уведомления → `.notifications`
- Профиль → `.profile(userID: "1")`
- Календарь → `.calendar`

**Входящие переходы:**
- Из любого экрана через таб-бар (первый таб)
- После авторизации (через `AppFlowManager`)

**Методы навигации:**
- `coordinator.showNotifications()` - переход на уведомления
- `coordinator.showProfile(for: "1")` - переход на профиль
- `coordinator.showCalendar()` - переход на календарь

#### 1.3.4. Данные

**Данные профиля:**
- `userName: String` - имя пользователя (из `Profile.name`)
- `avatar: String` - путь к изображению аватара

**Данные карусели:**
- Массив карточек с метриками (Daily score, статистика)
- Структура: `CarouselCardContent(id, content)`

**Данные событий:**
- Массив `TimelineEvent`
- Структура события:
  - `id: UUID`
  - `title: String`
  - `description: String`
  - `date: Date`
  - `type: EventType`

**Локальное хранение:**
- Кэш профиля: 5 минут
- Кэш событий: Зависит от реализации

#### 1.3.5. Обработка Ошибок

**Типы ошибок:**
- **Неавторизован (401):** Автоматический logout, переход на `.auth`
- **Сервер (500):** Логирование, отображение кэшированных данных
- **Сеть:** Логирование, использование кэша

**Стратегия обработки:**
- Ошибки загрузки профиля не блокируют экран
- Используются кэшированные данные при ошибках сети
- Пользователь может обновить данные pull-to-refresh (если реализовано)

#### 1.3.6. Аналитика

**Отслеживаемые события:**
- `screen_view: Home` - при появлении экрана
- `home_data_loaded` - при успешной загрузке данных
- `navigate_to_profile` - переход на профиль
- `navigate_to_calendar` - переход на календарь
- `navigate_to_notifications` - переход на уведомления
- `carousel_card_viewed` - просмотр карточки в карусели (параметры: `card_id`)

## 2. Pet List

### 2.1. Цель и Контекст

**Бизнес-задача:** Отображение списка всех питомцев пользователя с возможностью поиска, фильтрации и сортировки. Быстрый доступ к профилям питомцев и создание новых.

**Место в сценарии:** Доступен через навигацию из Home или через таб-бар (если реализовано). Является отправной точкой для работы с питомцами. После выбора питомца пользователь переходит на Pet Profile.

**Ключевые функции:** Поиск, фильтрация по типу, сортировка, создание нового питомца.

### 2.2. Элементы Интерфейса и Функциональность

#### 2.2.1. Структура Экрана

**Компонент: TitleTopWidget (Header)**
- Заголовок: "Мои питомцы" (локализованный)
- Правая иконка: Уведомления (`bell-20`) с badge "3"
- Аватар: Изображение `avatar`
- Отступы: Горизонтальные 20 points, верхний отступ 8 points

**Компонент: filterSection (Секция поиска и фильтров)**
- Позиция: Под header, фиксированная при прокрутке (опционально)

**SearchBarUI:**
- Placeholder: "Поиск по имени или породе..."
- Привязка: `$viewModel.searchText`
- Действие при поиске: `viewModel.applyFiltersAndSort()`
- Отступы: Горизонтальные 20 points

**Filter Chips (Фильтры):**

**Список питомцев:**

**Фиксированная кнопка "Добавить питомца":**

- Стиль: Primary button, размер large
- Иконка: `plus` (системная)
- Текст: "Добавить питомца"
- Действие: `viewModel.showCreatePet()`
- Градиентный фон: От прозрачного к непрозрачному (для визуального эффекта)

#### 2.2.4. Модальное Окно Сортировки

**Компонент: SortSheetView**
- Тип: Модальный sheet
- Заголовок: "Сортировка"
- Кнопка "Готово": Закрытие модального окна

**Варианты сортировки:**
- "Имя (А-Я)" (`.nameAsc`)
- "Имя (Я-А)" (`.nameDesc`)
- "Новые сначала" (`.dateNewest`)
- "Старые сначала" (`.dateOldest`)

**Визуализация:**
- Список вариантов с чекмарком у выбранного
- Выделение выбранного варианта (цвет primary с прозрачностью)
- Разделители между вариантами

**Действие:**

- Применение сортировки → `viewModel.applyFiltersAndSort()`
- Закрытие модального окна

#### 2.2.5. Интерактивность

**Поиск:**
- Ввод текста → автоматическое применение фильтров (через `onChange`)
- Поиск по полям: `pet.name`, `pet.breed`
- Регистронезависимый поиск

**Фильтрация:**
- Тап на фильтр → обновление `selectedFilter`
- Автоматическое применение фильтров
- Визуальное выделение выбранного фильтра

**Сортировка:**
- Тап на кнопку сортировки → открытие модального окна
- Выбор варианта → применение сортировки
- Закрытие модального окна

**Навигация:**
- Тап на карточку питомца → переход на `.petProfile(petId:)`
- Тап на "Добавить питомца" → переход на `.createPet`

- Потягивание вниз → обновление списка

#### 2.2.6. Валидация

**Валидация не требуется:**
- Экран информационный, пользовательский ввод только в поиске
- Поиск работает с любым текстом (даже пустым)

### 2.3. Техническая Реализация

#### 2.3.1. Сервисы и API

**API Endpoint: GET /pet/user**
- Метод: `GET`
- Путь: `/pet/user`
- Требует авторизации: Да (`requiresAuth: true`)
- Кэш: `cacheIfValid(300)` (5 минут)
- Retry: `exponential(maxAttempts: 3, initialDelay: 1.0)`

**Ответ при успехе (200 OK):**
```json
{
  "data": [
    {
      "id": 1,
      "name": "Луна",
      "type": "dog",
      "breed": "Бигль",
      "avatarPath": "url_to_avatar",
      "birthDate": "2014-01-01",
      "weight": 12.5,
      "color": "серый"
    }
  ]
}
```

**Use Case: FetchPetsUseCase**
- Входные данные: `Void`
- Выходные данные: `NetworkResult<[Pet]>`
- Действия:
  1. Вызов `PetNetworkService.fetchPets()`
  2. Конвертация DTO в Entities через `BackendConverter`
  3. Возврат массива `Pet`

#### 2.3.2. Состояния Экрана

**Состояние: Загрузка**
- `isLoading = true`
- Отображается `LoadingUI`
- Список скрыт

**Состояние: Успех**
- `pets` заполнен данными
- `filteredPets` обновлен после применения фильтров
- Список отображается

**Состояние: Пустое**
- `filteredPets.isEmpty = true`
- Отображается `EmptyStateUI`
- Кнопка "Добавить питомца" доступна

**Состояние: Ошибка**
- Alert с сообщением об ошибке
- Если `unauthorizedError` → автоматический logout
- Иначе → отображение ошибки, возможность повторить

#### 2.3.3. Логика Фильтрации и Сортировки

**Фильтрация:**
```swift
// Применение фильтра по типу
filtered = pets.filter { pet in
    selectedFilter.matches(pet)
}

// Применение поиска
if !searchText.isEmpty {
    filtered = filtered.filter { pet in
        pet.name.localizedCaseInsensitiveContains(searchText) ||
        pet.breed?.localizedCaseInsensitiveContains(searchText) ?? false
    }
}
```

**Сортировка:**
```swift
// По имени
case .nameAsc: return pet1.name < pet2.name
case .nameDesc: return pet1.name > pet2.name

// По дате (используется ID как прокси)
case .dateNewest: return pet1.id > pet2.id
case .dateOldest: return pet1.id < pet2.id
```

**Метод `applyFiltersAndSort()`:**
- Вызывается при:
  - Загрузке данных
  - Изменении `searchText`
  - Изменении `selectedFilter`
  - Изменении `selectedSort`

#### 2.3.4. Навигация

**Исходящие переходы:**
- Профиль питомца → `.petProfile(petId:)`
- Создание питомца → `.createPet`
- Уведомления → `.notifications` (из header)
- Профиль пользователя → `.profile(userID:)` (из header)

**Входящие переходы:**
- Из Home (через навигацию)
- Из таб-бара (если реализовано)
- После создания питомца (возврат назад)

**Методы навигации:**
- `coordinator.showPetProfile(for: petId)` - переход на профиль
- `coordinator.showCreatePet()` - переход на создание
- `coordinator.goBack()` - возврат назад

#### 2.3.5. Данные

**Модель Pet:**
```swift
struct Pet: Identifiable, Codable {
    let id: Int
    let name: String
    let type: PetType  // .dog, .cat, .bird
    let breed: String?
    let pasport: PetPassport?
    let photo: String?
    let notificationList: [PetNotification]?
}
```

**Состояние ViewModel:**
- `pets: [Pet]` - все загруженные питомцы
- `filteredPets: [Pet]` - отфильтрованные и отсортированные
- `searchText: String` - текст поиска
- `selectedFilter: PetFilterType` - выбранный фильтр
- `selectedSort: PetSortOption` - выбранная сортировка
- `showSortSheet: Bool` - флаг отображения модального окна

#### 2.3.6. Обработка Ошибок

**Типы ошибок:**
- **Неавторизован (401):** Автоматический logout, переход на `.auth`
- **Сервер (500):** Alert с сообщением, возможность повторить
- **Сеть:** Alert с предложением проверить подключение

**Стратегия обработки:**
- Ошибки логируются через `handleError()`
- Контекст: `["action": "load_pets"]`
- Пользователь может повторить загрузку

#### 2.3.7. Аналитика

**Отслеживаемые события:**
- `screen_view: PetList` - при появлении экрана
- `pets_loaded` - при успешной загрузке (параметры: `count`)
- `filter_changed` - при изменении фильтра (параметры: `filter`)
- `sort_changed` - при изменении сортировки (параметры: `sort`)
- `pet_profile_opened` - при открытии профиля (параметры: `pet_id`)
- `create_pet_opened` - при открытии создания питомца
