## 1. Social Feed (Лента)

### 1.1. Цель и Контекст

**Бизнес-задача:** Центральная лента социальной сети, где пользователи могут просматривать публикации от подписок, популярные посты и рекомендации. Создание среды для обмена опытом, знаниями и общения в сообществе владельцев питомцев.

**Место в сценарии:** Основной экран социальной сети, доступный через навигацию из Home или отдельный таб (если реализовано). Пользователь видит ленту публикаций, может взаимодействовать с ними и создавать свои.

**Ключевые функции:** Просмотр ленты, лайки, комментарии, репосты, подписки, поиск по хештегам.

### 1.2. Элементы Интерфейса и Функциональность

#### 1.2.1. Структура Экрана

**Компонент: Navigation Header**
- Заголовок: "Сообщество" или логотип приложения
- Кнопка поиска: В правом углу
- Иконка: `search-20`
- Действие: Переход на экран поиска

**Компонент: Tab Bar (Опционально)**
- Вкладки:
  - **Для вас** (рекомендации)
  - **Подписки** (только от подписок)
  - **Популярное** (топ публикации)
- Интерактивность: Переключение между вкладками

**Компонент: Post List**
- Тип: Вертикальный список публикаций
- Прокрутка: Вертикальный ScrollView
- Pull-to-Refresh: Обновление ленты
- Infinite Scroll: Автоматическая подгрузка при прокрутке

**Структура карточки публикации:**
- **Header:**
  - Аватар автора
  - Имя автора (кликабельно → профиль)
  - Время публикации (относительное: "2 часа назад")
  - Кнопка меню (опции: пожаловаться, скрыть)
- **Content:**
  - Изображение/видео (если есть)
  - Текст публикации
  - Хештеги (кликабельные)
  - Упоминания (@username)
- **Actions:**
  - Кнопка лайка (счетчик)
  - Кнопка комментариев (счетчик)
  - Кнопка репоста (счетчик)
  - Кнопка поделиться
- **Footer:**
  - Кнопка "Подписаться" (если не подписан)
  - Первые 2-3 комментария (опционально)

#### 1.2.2. Интерактивность

**Тап на публикацию:**
- Переход на детальный экран публикации
- Отображение всех комментариев
- Возможность комментирования

**Тап на лайк:**
- Переключение состояния (лайк/анлайк)
- Анимация: Сердечко с анимацией
- Обновление счетчика
- Аналитика: `post_liked` / `post_unliked`

**Тап на комментарии:**
- Переход на детальный экран с комментариями
- Или открытие модального окна с комментариями

**Тап на репост:**
- Модальное окно с опциями:
  - Репост в свою ленту
  - Репост в историю (stories)
  - Копировать ссылку
- Аналитика: `post_reposted`

**Тап на поделиться:**
- Системный share sheet
- Опции: Копировать ссылку, отправить в другое приложение

**Тап на хештег:**
- Переход на ленту по хештегу
- Отображение всех публикаций с этим хештегом

**Тап на упоминание (@username):**
- Переход на профиль упомянутого пользователя

**Тап на аватар/имя автора:**
- Переход на профиль автора

**Swipe влево (опционально):**
- Быстрый лайк (как в Instagram)

**Pull-to-Refresh:**
- Обновление ленты
- Вызов `viewModel.refreshFeed()`

#### 1.2.3. Валидация

**Валидация не требуется:**
- Экран информационный, пользовательский ввод только в комментариях (на детальном экране)

### 1.3. Техническая Реализация

#### 1.3.1. Сервисы и API

**API Endpoint: GET /social/feed**
- Метод: `GET`
- Путь: `/social/feed`
- Требует авторизации: Да (`requiresAuth: true`)
- Query параметры:
  - `page`: Номер страницы
  - `limit`: Количество на странице (по умолчанию 20)
  - `type`: Тип ленты (`for_you` | `following` | `popular`)
  - `hashtag`: Фильтр по хештегу (опционально)
- Кэш: `cacheIfValid(300)` (5 минут)
- Retry: `exponential(maxAttempts: 3, initialDelay: 1.0)`

**Ответ при успехе (200 OK):**
```json
{
  "data": [
    {
      "id": "post_123",
      "author": {
        "id": "user_456",
        "username": "petlover",
        "avatar": "url_to_avatar",
        "isVerified": false
      },
      "content": {
        "text": "Мой питомец сегодня... #здоровьекошки",
        "images": ["url_to_image1", "url_to_image2"],
        "video": null
      },
      "hashtags": ["здоровьекошки", "кошки"],
      "mentions": ["@vetclinic"],
      "stats": {
        "likes": 150,
        "comments": 25,
        "reposts": 10,
        "views": 500
      },
      "isLiked": false,
      "isReposted": false,
      "createdAt": "2025-01-15T10:30:00Z",
      "updatedAt": "2025-01-15T10:30:00Z"
    }
  ],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 500,
    "hasMore": true
  }
}
```

**Use Case: FetchFeedUseCase**
- Входные данные: `FeedRequest(type, page, limit, hashtag?)`
- Выходные данные: `NetworkResult<[Post]>`
- Действия:
  1. Создание `NetworkRequest` с query параметрами
  2. Вызов `SocialNetworkService.fetchFeed()`
  3. Конвертация DTO в Entities
  4. Возврат массива `Post`

**Use Case: LikePostUseCase**
- Входные данные: `PostId`
- Выходные данные: `NetworkResult<PostStats>`
- Действия:
  1. Отправка запроса на лайк/анлайк
  2. Обновление статистики поста
  3. Возврат обновленной статистики

#### 1.3.2. Состояния Экрана

**Состояние: Загрузка**
- Индикатор загрузки
- Placeholder для списка

**Состояние: Успех**
- Лента публикаций отображается
- Карточки заполнены данными
- Применены фильтры (если выбраны)

**Состояние: Пустое**
- Если нет публикаций → отображается пустое состояние
- Иконка и текст "Нет публикаций"
- Предложение подписаться на пользователей

**Состояние: Ошибка**
- Alert с сообщением об ошибке
- Возможность повторить загрузку

**Состояние: Загрузка следующей страницы**
- Индикатор внизу списка
- Автоматическая подгрузка при прокрутке

#### 1.3.3. Навигация

**Входящие переходы:**
- Из Home (навигация)
- Из Profile (кнопка "Мои публикации")

**Исходящие переходы:**
- Детальный просмотр → `.postDetail(postId:)`
- Профиль автора → `.userProfile(userId:)`
- Лента по хештегу → `.hashtagFeed(hashtag:)`
- Создание публикации → `.createPost`

**Методы навигации:**
- Открытие: `coordinator.showSocialFeed()`
- Детальный просмотр: `coordinator.showPostDetail(id:)`
- Профиль: `coordinator.showUserProfile(id:)`
- Хештег: `coordinator.showHashtagFeed(hashtag:)`

#### 1.3.4. Данные

**Post:**
```swift
struct Post: Identifiable, Codable {
    let id: String
    let author: User
    let content: PostContent
    let hashtags: [String]
    let mentions: [String]
    let stats: PostStats
    let isLiked: Bool
    let isReposted: Bool
    let createdAt: Date
    let updatedAt: Date
}

struct PostContent: Codable {
    let text: String
    let images: [String]?
    let video: String?
}

struct PostStats: Codable {
    let likes: Int
    let comments: Int
    let reposts: Int
    let views: Int
}
```

#### 1.3.5. Обработка Ошибок

**Типы ошибок:**
- **NetworkError:** Ошибка сети
- **Unauthorized:** Не авторизован
- **ServerError:** Ошибка сервера

**Отображение ошибок:**
- Alert с понятным сообщением
- Возможность повторить загрузку
- Логирование через `Logger`

#### 1.3.6. Аналитика

**Отслеживаемые события:**
- `screen_view: SocialFeed` - при появлении экрана
- `feed_refreshed` - обновление ленты
- `post_liked` - лайк публикации (параметры: `post_id`)
- `post_unliked` - анлайк публикации (параметры: `post_id`)
- `post_commented` - комментарий (параметры: `post_id`)
- `post_reposted` - репост (параметры: `post_id`)
- `hashtag_tapped` - тап на хештег (параметры: `hashtag`)
- `user_profile_opened` - открытие профиля (параметры: `user_id`)

## 2. Post Detail (Детальный просмотр публикации)

### 2.1. Цель и Контекст

**Бизнес-задача:** Детальный просмотр публикации со всеми комментариями, возможностью комментирования и взаимодействия. Полный контекст обсуждения.

**Место в сценарии:** Открывается при тапе на публикацию из ленты или из уведомлений. Пользователь может просмотреть все комментарии, добавить свой комментарий, лайкнуть или репостнуть.

### 2.2. Элементы Интерфейса и Функциональность

#### 2.2.1. Структура Экрана

**Компонент: Post Header**
- Полная информация о публикации (как в ленте)
- Все действия (лайк, комментарий, репост, поделиться)

**Компонент: Comments Section**
- Заголовок: "Комментарии (N)"
- Список комментариев:
  - Аватар автора
  - Имя автора
  - Текст комментария
  - Время комментария
  - Кнопка лайка (если реализовано)
  - Кнопка ответа (если реализовано)
- Прокрутка: Вертикальный ScrollView
- Infinite Scroll: Подгрузка комментариев

**Компонент: Comment Input**
- Позиция: Фиксированная внизу экрана
- Поле ввода: Многострочное текстовое поле
- Кнопка отправки: Иконка отправки
- Placeholder: "Написать комментарий..."
- Действие: `viewModel.addComment(text:)`

#### 2.2.2. Интерактивность

**Добавление комментария:**
- Ввод текста в поле
- Тап на кнопку отправки
- Валидация: Текст не пустой
- Отправка комментария
- Обновление списка комментариев

**Лайк комментария (если реализовано):**
- Тап на иконку лайка
- Обновление счетчика

**Ответ на комментарий (если реализовано):**
- Тап на "Ответить"
- Открытие поля ввода с упоминанием автора
- Отправка ответа

### 2.3. Техническая Реализация

#### 2.3.1. Сервисы и API

**API Endpoint: GET /social/posts/{postId}**
- Метод: `GET`
- Путь: `/social/posts/{postId}`
- Требует авторизации: Да

**API Endpoint: GET /social/posts/{postId}/comments**
- Метод: `GET`
- Путь: `/social/posts/{postId}/comments`
- Query параметры: `page`, `limit`

**API Endpoint: POST /social/posts/{postId}/comments**
- Метод: `POST`
- Путь: `/social/posts/{postId}/comments`
- Тело: `{ "text": "string" }`

**Use Case: FetchPostDetailUseCase**
- Входные данные: `PostId`
- Выходные данные: `NetworkResult<Post>`

**Use Case: FetchCommentsUseCase**
- Входные данные: `PostId, page, limit`
- Выходные данные: `NetworkResult<[Comment]>`

**Use Case: AddCommentUseCase**
- Входные данные: `AddCommentInput(postId, text)`
- Выходные данные: `NetworkResult<Comment>`

## 3. Create Post (Создание публикации)

### 3.1. Цель и Контекст

**Бизнес-задача:** Создание новой публикации с возможностью добавления фото/видео, текста, хештегов и упоминаний. Публикация в ленту сообщества.

**Место в сценарии:** Доступен через кнопку "+" в навигации или из ленты. После создания публикация появляется в ленте автора.

### 3.2. Элементы Интерфейса и Функциональность

#### 3.2.1. Структура Экрана

**Компонент: Navigation Header**
- Заголовок: "Новая публикация"
- Кнопка "Отмена": Слева
- Кнопка "Опубликовать": Справа (активна при валидных данных)

**Компонент: Media Picker**
- Кнопка добавления фото/видео
- Галерея выбранных медиа
- Возможность удаления выбранных
- Ограничение: До 10 изображений или 1 видео

**Компонент: Text Input**
- Многострочное текстовое поле
- Placeholder: "Что у вас нового?"
- Поддержка хештегов (#) и упоминаний (@)
- Счетчик символов (опционально, лимит 2000)

**Компонент: Hashtag Suggestions**
- Автодополнение при вводе "#"
- Список популярных хештегов
- Кликабельные предложения

**Компонент: Mention Suggestions**
- Автодополнение при вводе "@"
- Список пользователей для упоминания
- Кликабельные предложения

**Компонент: Privacy Settings (Опционально)**
- Выбор видимости: Публичная / Только подписчики / Приватная

### 3.3. Техническая Реализация

#### 3.3.1. Сервисы и API

**API Endpoint: POST /social/posts**
- Метод: `POST`
- Путь: `/social/posts`
- Content-Type: `multipart/form-data`
- Тело:
  - `text`: Текст публикации
  - `images[]`: Массив изображений
  - `video`: Видео (опционально)
  - `hashtags[]`: Массив хештегов
  - `mentions[]`: Массив упоминаний
  - `privacy`: Уровень приватности

**Use Case: CreatePostUseCase**
- Входные данные: `CreatePostInput(content, media, hashtags, mentions)`
- Выходные данные: `NetworkResult<Post>`

## 4. User Profile (Профиль пользователя)

### 4.1. Цель и Контекст

**Бизнес-задача:** Просмотр профиля пользователя с его публикациями, информацией и возможностью подписки. Профиль может быть собственным или другого пользователя.

**Место в сценарии:** Открывается при тапе на аватар/имя из ленты или при поиске пользователей.

### 4.2. Элементы Интерфейса и Функциональность

#### 4.2.1. Структура Экрана

**Компонент: Profile Header**
- Аватар пользователя (большой)
- Имя пользователя
- Username (@username)
- Описание/био
- Статистика:
  - Публикации: N
  - Подписчики: N
  - Подписки: N
- Кнопка "Подписаться" / "Отписаться" (если не свой профиль)
- Кнопка "Редактировать профиль" (если свой профиль)

**Компонент: Posts Grid**
- Сетка публикаций пользователя (3 колонки)
- Тап на публикацию → детальный просмотр
- Infinite Scroll: Подгрузка публикаций

### 4.3. Техническая Реализация

#### 4.3.1. Сервисы и API

**API Endpoint: GET /social/users/{userId}**
- Метод: `GET`
- Путь: `/social/users/{userId}`

**API Endpoint: POST /social/users/{userId}/follow**
- Метод: `POST`
- Путь: `/social/users/{userId}/follow`

**Use Case: FetchUserProfileUseCase**
- Входные данные: `UserId`
- Выходные данные: `NetworkResult<UserProfile>`

**Use Case: FollowUserUseCase**
- Входные данные: `UserId`
- Выходные данные: `NetworkResult<Void>`

## 5. Hashtag Feed (Лента по хештегу)

### 5.1. Цель и Контекст

**Бизнес-задача:** Просмотр всех публикаций с определенным хештегом. Навигация по темам и интересам сообщества.

**Место в сценарии:** Открывается при тапе на хештег из публикации или при поиске.

### 5.2. Элементы Интерфейса и Функциональность

#### 5.2.1. Структура Экрана

**Компонент: Hashtag Header**
- Хештег: #название (крупный шрифт)
- Статистика:
  - Количество публикаций
  - Популярность (тренд)
- Кнопка "Подписаться на хештег" (опционально)

**Компонент: Post List**
- Список публикаций с этим хештегом
- Фильтры: Новые / Популярные
- Infinite Scroll

### 5.3. Техническая Реализация

#### 5.3.1. Сервисы и API

**API Endpoint: GET /social/hashtags/{hashtag}/posts**
- Метод: `GET`
- Путь: `/social/hashtags/{hashtag}/posts`
- Query параметры: `page`, `limit`, `sort` (new|popular)

**Use Case: FetchHashtagPostsUseCase**
- Входные данные: `Hashtag, page, limit, sort`
- Выходные данные: `NetworkResult<[Post]>`
