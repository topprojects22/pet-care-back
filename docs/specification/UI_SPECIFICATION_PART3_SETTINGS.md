## 1. Edit Profile (Редактирование профиля)

### 1.1. Цель и Контекст

**Бизнес-задача:** Редактирование личной информации пользователя: фото, имя, email, телефон. Обновление данных профиля для корректного отображения в приложении и при взаимодействии с другими пользователями.

**Место в сценарии:** Доступен из Profile экрана через кнопку "Редактировать профиль" или пункт меню. После сохранения изменения применяются к профилю пользователя.

**Ключевые функции:** Изменение фото, редактирование личных данных, валидация, сохранение изменений.

### 1.2. Элементы Интерфейса и Функциональность

#### 1.2.1. Структура Экрана

**Компонент: Navigation Header**
- Заголовок: "Редактировать профиль" (локализованный)
- Кнопка "Назад": В левом углу
- Иконка: `left-arrow-20`
- Действие: `viewModel.navigateBack()`

**Компонент: Photo Picker Section**
- Тип: `PhotoPickerSectionWidget`
- Содержимое:
  - Текущее фото профиля (если есть)
  - Или placeholder с иконкой камеры
  - Кнопка "Изменить фото"
- Действие: Тап → открытие системного фото-пикера
- Поддержка: Выбор из галереи или камера

**Компонент: Profile Information Section**
- Заголовок секции: "Основная информация"
- Поля ввода:
  - **Имя:**
    - Компонент: `TextFieldUI`
    - Placeholder: "Имя"
    - Иконка: `person.fill` (системная)
    - Привязка: `$viewModel.name`
    - Ошибка: `viewModel.nameError`
    - Валидация: Обязательное поле, минимум 2 символа
  - **Email:**
    - Компонент: `TextFieldUI`
    - Placeholder: "Email"
    - Иконка: `envelope.fill` (системная)
    - Привязка: `$viewModel.email`
    - Ошибка: `viewModel.emailError`
    - Конфигурация: `keyboardType: .emailAddress`
    - Валидация: Формат email, обязательное поле
  - **Телефон:**
    - Компонент: `TextFieldUI`
    - Placeholder: "Телефон"
    - Иконка: `phone.fill` (системная)
    - Привязка: `$viewModel.phone`
    - Ошибка: `viewModel.phoneError`
    - Конфигурация: `keyboardType: .phonePad`
    - Валидация: Формат телефона (опционально)

**Компонент: Save Button**
- Тип: `ButtonUI`
- Стиль: Primary button, размер large
- Текст: "Сохранить" (локализованный)
- Состояния:
  - Активна: Когда форма валидна (`isFormValid`)
  - Неактивна: Во время загрузки или при невалидных данных
  - Загрузка: Показывает индикатор загрузки
- Действие: `viewModel.saveProfile()`

#### 1.2.2. Интерактивность

**Выбор фото:**
- Тап на фото или кнопку "Изменить фото"
- Открытие системного фото-пикера
- Выбор фото из галереи или съемка нового
- Обновление превью фото
- Загрузка фото на сервер (при сохранении)

**Редактирование полей:**
- Ввод данных в поля
- Валидация в реальном времени
- Ошибки отображаются под полями
- Автоочистка ошибок при исправлении

**Сохранение:**
- Тап на "Сохранить"
- Валидация всех полей
- Если валидно: Отправка на сервер
- Если невалидно: Отображение ошибок

#### 1.2.3. Валидация Данных

**Имя:**
- Обязательное поле
- Минимальная длина: 2 символа
- Максимальная длина: 50 символов
- Сообщение об ошибке: "Имя должно содержать минимум 2 символа"

**Email:**
- Обязательное поле
- Формат: Стандартный email (regex)
- Уникальность: Проверяется на сервере
- Сообщение об ошибке: "Введите корректный email" или "Email уже используется"

**Телефон:**
- Опциональное поле
- Формат: Международный формат (опционально)
- Сообщение об ошибке: "Введите корректный номер телефона"

### 1.3. Техническая Реализация

#### 1.3.1. Сервисы и API

**API Endpoint: GET /user/profile**
- Метод: `GET`
- Путь: `/user/profile`
- Требует авторизации: Да (`requiresAuth: true`)
- Ответ при успехе (200 OK):
```json
{
  "id": "user_123",
  "name": "Иван Иванов",
  "email": "ivan@example.com",
  "phone": "+79001234567",
  "avatar": "url_to_avatar",
  "createdAt": "2025-01-01T00:00:00Z"
}
```

**API Endpoint: PUT /user/profile**
- Метод: `PUT`
- Путь: `/user/profile`
- Требует авторизации: Да
- Content-Type: `multipart/form-data` (если есть фото)
- Тело запроса:
```json
{
  "name": "Иван Иванов",
  "email": "ivan@example.com",
  "phone": "+79001234567"
}
```
- Файл: `avatar` (если изменено фото)

**Ответ при успехе (200 OK):**
```json
{
  "id": "user_123",
  "name": "Иван Иванов",
  "email": "ivan@example.com",
  "phone": "+79001234567",
  "avatar": "url_to_new_avatar",
  "updatedAt": "2025-01-15T10:30:00Z"
}
```

**Use Case: FetchUserProfileUseCase**
- Входные данные: `Void` (используется текущий пользователь)
- Выходные данные: `NetworkResult<UserProfile>`

**Use Case: UpdateUserProfileUseCase**
- Входные данные: `UpdateProfileInput(name, email, phone, avatar?)`
- Выходные данные: `NetworkResult<UserProfile>`
- Действия:
  1. Валидация данных
  2. Загрузка фото (если изменено)
  3. Создание `NetworkRequest`
  4. Вызов `NetworkService.request()`
  5. Обновление локального профиля
  6. Возврат обновленного профиля

#### 1.3.2. Состояния Экрана

**Состояние: Загрузка профиля**
- Индикатор загрузки
- Placeholder для полей

**Состояние: Отображение формы**
- Поля заполнены данными профиля
- Фото отображается (если есть)
- Кнопка сохранения активна/неактивна в зависимости от валидности

**Состояние: Сохранение**
- Индикатор загрузки на кнопке
- Все поля заблокированы
- Кнопка неактивна

**Состояние: Успех**
- Профиль обновлен
- Закрытие экрана или возврат на Profile
- Уведомление об успешном сохранении (опционально)

**Состояние: Ошибка**
- Alert с сообщением об ошибке
- Ошибки валидации под полями
- Кнопка снова активна
- Возможность повторить попытку

#### 1.3.3. Навигация

**Входящие переходы:**
- Из Profile (кнопка "Редактировать профиль")

**Исходящие переходы:**
- Успешное сохранение → возврат на Profile
- Отмена → возврат на Profile

**Методы навигации:**
- Открытие: `coordinator.showEditProfile()`
- Закрытие: `coordinator.goBack()`

#### 1.3.4. Данные

**UserProfile:**
```swift
struct UserProfile: Codable {
    let id: String
    let name: String
    let email: String
    let phone: String?
    let avatar: String?
    let createdAt: Date
    let updatedAt: Date?
}
```

**UpdateProfileInput:**
```swift
struct UpdateProfileInput {
    let name: String
    let email: String
    let phone: String?
    let avatar: UIImage?
}
```

#### 1.3.5. Обработка Ошибок

**Типы ошибок:**
- **Валидация (400):** Неверный формат данных
- **Конфликт (409):** Email уже используется
- **Неавторизован (401):** Требуется авторизация
- **Сервер (500):** Внутренняя ошибка сервера
- **Сеть:** Отсутствие интернета

**Отображение ошибок:**
- Ошибки валидации: Под соответствующими полями
- Ошибки сервера: Alert с сообщением
- Специфичные ошибки: "Email уже используется" → под полем Email

#### 1.3.6. Аналитика

**Отслеживаемые события:**
- `screen_view: EditProfile` - при появлении экрана
- `profile_photo_changed` - изменение фото профиля
- `profile_updated` - успешное обновление профиля (параметры: `fields_changed`)
- `profile_update_failed` - ошибка обновления (параметры: `error_code`)

## 2. Language Settings (Настройки языка)

### 2.1. Цель и Контекст

**Бизнес-задача:** Выбор языка интерфейса приложения. Поддержка локализации для удобства пользователей из разных стран.

**Место в сценарии:** Доступен из Profile экрана через пункт меню "Язык" или из Settings. После выбора языка интерфейс обновляется немедленно.

**Ключевые функции:** Выбор языка из списка доступных, применение изменений.

### 2.2. Элементы Интерфейса и Функциональность

#### 2.2.1. Структура Экрана

**Компонент: Navigation Header**
- Заголовок: "Язык" (локализованный)
- Кнопка "Назад": В левом углу
- Иконка: `left-arrow-20`
- Действие: `viewModel.navigateBack()`

**Компонент: Language List**
- Тип: Вертикальный список языков
- Прокрутка: Вертикальный ScrollView
- Элементы: Карточки языков

**Структура карточки языка:**
- Компонент: `SettingsCardUI`
- Содержимое:
  - Иконка: `internet-20`
  - Название языка: Полное название (например, "Русский", "English")
  - Индикатор выбора: Checkmark или выделение (если выбран)
- Тип: `.change` (если выбран) или `.def` (если не выбран)
- Действие: Тап → `viewModel.selectLanguage(languageCode)`

**Доступные языки:**
- Русский (`ru`)
- English (`en`)
- Другие (если поддерживаются)

#### 2.2.2. Интерактивность

**Выбор языка:**
- Тап на карточку языка
- Обновление выбранного языка
- Применение изменений немедленно
- Обновление интерфейса
- Сохранение выбора в настройках

#### 2.2.3. Валидация

**Валидация не требуется:**
- Экран информационный, выбор из предопределенного списка

### 2.3. Техническая Реализация

#### 2.3.1. Сервисы и API

**API вызовы отсутствуют:**
- Язык сохраняется локально в `UserDefaults` или `SettingsManager`
- Применение через систему локализации iOS

**Локальные операции:**
- Загрузка текущего языка: `viewModel.loadCurrentLanguage()`
- Сохранение выбранного языка: `SettingsManager.shared.setLanguage(code)`
- Применение языка: Обновление `Bundle` и перезагрузка интерфейса

#### 2.3.2. Состояния Экрана

**Состояние: Загрузка**
- Загрузка текущего языка
- Отображение списка языков

**Состояние: Отображение**
- Список языков отображается
- Выбранный язык выделен
- Кнопки активны

**Состояние: Применение изменений**
- Индикатор загрузки (опционально)
- Обновление интерфейса
- Возврат на предыдущий экран

#### 2.3.3. Навигация

**Входящие переходы:**
- Из Profile (пункт меню "Язык")
- Из Settings (если реализовано)

**Исходящие переходы:**
- После выбора языка → возврат на предыдущий экран

**Методы навигации:**
- Открытие: `coordinator.showLanguageSettings()`
- Закрытие: `coordinator.goBack()`

#### 2.3.4. Данные

**Language:**
```swift
struct Language: Identifiable {
    let code: String
    let name: String
    let nativeName: String
}
```

**Доступные языки:**
```swift
let availableLanguages: [Language] = [
    Language(code: "ru", name: "Russian", nativeName: "Русский"),
    Language(code: "en", name: "English", nativeName: "English")
]
```

#### 2.3.5. Обработка Ошибок

**Ошибки не ожидаются:**
- Операция локальная, не требует сетевых запросов

#### 2.3.6. Аналитика

**Отслеживаемые события:**
- `screen_view: LanguageSettings` - при появлении экрана
- `language_changed` - изменение языка (параметры: `language_code`, `previous_language`)

## 3. Feedback (Обратная связь)

### 3.1. Цель и Контекст

**Бизнес-задача:** Форма обратной связи для пользователей. Возможность сообщить о проблемах, предложить улучшения или задать вопросы команде разработки.

**Место в сценарии:** Доступен из Profile экрана через пункт меню "Обратная связь". После отправки пользователь получает подтверждение.

**Ключевые функции:** Ввод темы и сообщения, отправка обратной связи, подтверждение отправки.

### 3.2. Элементы Интерфейса и Функциональность

#### 3.2.1. Структура Экрана

**Компонент: Navigation Header**
- Заголовок: "Обратная связь" (локализованный)
- Кнопка "Назад": В левом углу
- Иконка: `left-arrow-20`
- Действие: `viewModel.navigateBack()`

**Компонент: Subject Section**
- Заголовок секции: "Тема"
- Поле ввода:
  - Компонент: `TextFieldUI`
  - Placeholder: "Тема обращения"
  - Иконка: `text.bubble` (системная)
  - Привязка: `$viewModel.subject`
  - Ошибка: `viewModel.subjectError`
  - Валидация: Обязательное поле, минимум 3 символа

**Компонент: Message Section**
- Заголовок секции: "Сообщение"
- Поле ввода:
  - Компонент: `TextAreaUI`
  - Placeholder: "Опишите вашу проблему или предложение..."
  - Привязка: `$viewModel.message`
  - Ошибка: `viewModel.messageError`
  - Минимальная высота: 150 points
  - Валидация: Обязательное поле, минимум 10 символов

**Компонент: Submit Button**
- Тип: `ButtonUI`
- Стиль: Primary button, размер large
- Текст: "Отправить" (локализованный)
- Состояния:
  - Активна: Когда форма валидна (`isFormValid`)
  - Неактивна: Во время загрузки или при невалидных данных
  - Загрузка: Показывает индикатор загрузки
- Действие: `viewModel.submitFeedback()`

**Компонент: Success Alert**
- Тип: Alert
- Заголовок: "Спасибо за обратную связь!"
- Сообщение: "Ваше сообщение отправлено. Мы свяжемся с вами в ближайшее время."
- Кнопка: "OK" → закрытие alert и возврат назад

#### 3.2.2. Интерактивность

**Ввод данных:**
- Ввод темы и сообщения
- Валидация в реальном времени
- Ошибки отображаются под полями
- Автоочистка ошибок при исправлении

**Отправка обратной связи:**
- Тап на "Отправить"
- Валидация всех полей
- Если валидно: Отправка на сервер
- Если невалидно: Отображение ошибок

**После успешной отправки:**
- Отображение Alert с благодарностью
- Автоматический возврат на предыдущий экран

#### 3.2.3. Валидация Данных

**Тема:**
- Обязательное поле
- Минимальная длина: 3 символа
- Максимальная длина: 100 символов
- Сообщение об ошибке: "Тема должна содержать минимум 3 символа"

**Сообщение:**
- Обязательное поле
- Минимальная длина: 10 символов
- Максимальная длина: 2000 символов
- Сообщение об ошибке: "Сообщение должно содержать минимум 10 символов"

### 3.3. Техническая Реализация

#### 3.3.1. Сервисы и API

**API Endpoint: POST /feedback**


- Входные данные: `FeedbackInput(subject, message)`
- Выходные данные: `NetworkResult<FeedbackResponse>`

  1. Валидация данных
  2. Создание `NetworkRequest`
  3. Вызов `NetworkService.request()`
  4. Обработка ответа
  5. Возврат результата

#### 3.3.2. Состояния Экрана

- Поля пустые
- Кнопка отправки неактивна (пока форма не валидна)

**Состояние: Загрузка**
- Индикатор загрузки на кнопке
- Все поля заблокированы
- Кнопка неактивна

**Состояние: Успех**
- Alert с благодарностью
- Автоматический возврат на предыдущий экран

**Состояние: Ошибка**
- Alert с сообщением об ошибке
- Ошибки валидации под полями
- Кнопка снова активна
- Возможность повторить попытку

#### 3.3.3. Навигация

**Входящие переходы:**
- Из Profile (пункт меню "Обратная связь")

**Исходящие переходы:**
- Успешная отправка → возврат на Profile
- Отмена → возврат на Profile

**Методы навигации:**
- Открытие: `coordinator.showFeedback()`
- Закрытие: `coordinator.goBack()`

```swift
struct FeedbackResponse: Codable {
```

- Ошибки валидации: Под соответствующими полями

- `feedback_failed` - ошибка отправки (параметры: `error_code`)

## 4. Delivery Address (Адрес доставки)

### 4.1. Цель и Контекст

**Бизнес-задача:** Управление адресами доставки для заказов товаров и услуг. Добавление, редактирование и удаление адресов доставки.

**Место в сценарии:** Доступен из Cart при оформлении заказа или из Profile для управления адресами. Используется при заказе товаров для питомцев.

**Ключевые функции:** Добавление адреса, редактирование, удаление, выбор адреса по умолчанию.

### 4.3. Техническая Реализация

#### 4.3.1. Сервисы и API

**API Endpoint: GET /user/addresses**
- Метод: `GET`
- Путь: `/user/addresses`
- Требует авторизации: Да

**API Endpoint: POST /user/addresses**
- Метод: `POST`
- Путь: `/user/addresses`
- Тело запроса:
```json
{
  "type": "home",
  "city": "Москва",
  "street": "ул. Примерная",
  "house": "1",
  "apartment": "10",
  "postalCode": "123456",
  "recipientName": "Иван Иванов",
  "phone": "+79001234567",
  "isDefault": true
}
```

**API Endpoint: PUT /user/addresses/{addressId}**
- Метод: `PUT`
- Путь: `/user/addresses/{addressId}`

**API Endpoint: DELETE /user/addresses/{addressId}**
- Метод: `DELETE`
- Путь: `/user/addresses/{addressId}`

#### 4.3.4. Данные

**DeliveryAddress:**
```swift
struct DeliveryAddress: Identifiable, Codable {
    let id: String
    let type: AddressType
    let city: String
    let street: String
    let house: String
    let apartment: String?
    let postalCode: String
    let recipientName: String
    let phone: String
    let isDefault: Bool
    let createdAt: Date
    let updatedAt: Date?
}

enum AddressType: String, Codable {
    case home = "home"
    case work = "work"
    case other = "other"
}
```

#### 4.3.5. Обработка Ошибок

**Типы ошибок:**
- **Валидация (400):** Неверный формат данных
- **Неавторизован (401):** Требуется авторизация
- **Сервер (500):** Внутренняя ошибка сервера
- **Сеть:** Отсутствие интернета

**Отображение ошибок:**
- Ошибки валидации: Под соответствующими полями
- Ошибки сервера: Alert с сообщением
