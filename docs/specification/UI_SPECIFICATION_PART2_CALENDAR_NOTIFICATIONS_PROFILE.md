## 1. Calendar

### 1.1. Цель и Контекст

**Бизнес-задача:** Календарь событий для управления расписанием питомцев: прививки, визиты к ветеринару, обработки, прием лекарств. Визуализация событий по датам и возможность добавления новых.

**Место в сценарии:** Доступен из Home Screen (кнопка "All events") или через таб-бар. Является центральным инструментом для планирования ухода за питомцами.

**Ключевые функции:** Просмотр событий по датам, добавление/редактирование событий, навигация по месяцам.

### 1.2. Элементы Интерфейса и Функциональность

#### 1.2.1. Структура Экрана

**Компонент: TitleTopWidget (Header)**
- Заголовок: "Calendar" (локализованный)
- Левая иконка: Стрелка назад (`left-arrow-20`)
  - Действие: `viewModel.navigateBack()`
- Правая иконка: Редактирование (`edit-20`)
  - Действие: `viewModel.showAddEvent()`
- Отступы: Горизонтальные 20 points

**Компонент: MonthListWidget**
- Тип: Горизонтальный список месяцев
- Количество: 24 месяца (2 года вперед)
- Начальная дата: 1 год назад от текущей даты
- Текущая дата: `viewModel.currentDate`
- Действие: Тап на месяц → обновление `currentDate`
- Отступы: Нижний padding

**Компонент: CalendarUI**
- Тип: Календарная сетка
- Привязки:
  - `selectedDate: $viewModel.selectedDate`
  - `currentDate: viewModel.currentDate`
  - `markedDates: viewModel.getMarkedDates()`
- Действия:
  - `onDateSelected`: Обновление `selectedDate`
  - `onMonthChanged`: Обновление `currentDate`
- Визуализация:
  - Выделение выбранной даты
  - Отметка дат с событиями (точки или другие индикаторы)
- ID: `viewModel.currentDate` (для принудительного обновления)

**Секция "События выбранной даты" (selectedDateEventsSection):**
- Заголовок: Форматированная дата (например, "15 января 2025")
  - Формат: "d MMMM yyyy" (русская локаль)
  - Стиль: 18pt, semibold
- Кнопка "Добавить":
  - Иконка: `plus.circle.fill`
  - Текст: "Добавить"
  - Действие: `viewModel.showAddEvent(for: selectedDate)`
  - Цвет: Primary
- Содержимое:
  - **Пустое состояние:**
    - Компонент: `EmptyStateUI`
    - Иконка: `calendar.badge.plus`
    - Заголовок: "Нет событий"
    - Сообщение: "На этот день не запланировано событий"
  - **Список событий:**
    - Тип: Вертикальный ScrollView
    - Компонент: `DateCardUI`
    - Отступы: Вертикальные 8 points

**Компонент DateCardUI:**
- Структура:
  - `id`: UUID события (строка)
  - `dateTitle`: Время начала (например, "с 10:00")
  - `timeTitle`: Время окончания (например, "до 11:00")
  - `title`: Название события
  - `description`: Описание события
  - `action`: Действие при тапе (редактирование)
- Действие: Тап на карточку → `viewModel.showEditEvent(event)`

**Модальное окно AddEventView:**
- Тип: Sheet
- Привязка: `$viewModel.showAddEventSheet`
- Параметры:
  - `viewModel: CalendarViewModel`
  - `initialDate: viewModel.selectedDate`
- Действие: Добавление или редактирование события

#### 1.2.2. Интерактивность

**Навигация по месяцам:**
- Тап на месяц в `MonthListWidget` → обновление `currentDate`
- Swipe в календаре → смена месяца
- Действие: `viewModel.setCurrentDate(by: date)`

**Выбор даты:**
- Тап на дату в календаре → обновление `selectedDate`
- Действие: `viewModel.setSelectedDate(date)`
- Автоматическое обновление списка событий

**Добавление события:**
- Тап на иконку редактирования → открытие модального окна
- Тап на кнопку "Добавить" → открытие модального окна для выбранной даты
- Действие: `viewModel.showAddEvent(for: date)`

**Редактирование события:**
- Тап на карточку события → открытие модального окна редактирования
- Действие: `viewModel.showEditEvent(event)`

**Удаление события:**
- В модальном окне редактирования (если реализовано)
- Действие: `viewModel.deleteEvent(event)`

#### 1.2.3. Валидация

**Валидация не требуется:**
- Экран информационный, пользовательский ввод только в модальном окне
- Валидация происходит в `AddEventView`

#### 1.3.4. Данные

**Модель EventItem:**
```swift
struct EventItem: Identifiable {
    let id: UUID
    let title: String
    let description: String
    let date: Date
    let startTime: Date
    let endTime: Date
    
    var dateTitle: String // "с 10:00"
    var timeTitle: String // "до 11:00"
}
```

**Состояние ViewModel:**
- `selectedDate: Date` - выбранная дата
- `currentDate: Date` - текущий месяц
- `events: [EventItem]` - все события
- `showAddEventSheet: Bool` - флаг модального окна
- `eventToEdit: EventItem?` - событие для редактирования

**Методы:**
- `getEvents(for: Date) -> [EventItem]` - события для даты
- `getMarkedDates() -> Set<Date>` - даты с событиями
- `addEvent(_:)` - добавление события
- `updateEvent(_:)` - обновление события
- `deleteEvent(_:)` - удаление события

#### 1.3.5. Обработка Ошибок

**Типы ошибок:**
- **Неавторизован (401):** Автоматический logout
- **Сервер (500):** Общая ошибка сервера
- **Сеть:** Ошибка подключения

**Стратегия обработки:**
- Ошибки логируются через `handleError()`
- Пользователь может повторить операцию

#### 1.3.6. Аналитика

**Отслеживаемые события:**
- `screen_view: Calendar` - при появлении экрана
- `calendar_event_added` - при добавлении (параметры: `event_title`)
- `calendar_event_updated` - при обновлении (параметры: `event_title`)
- `calendar_event_deleted` - при удалении (параметры: `event_title`)
- `calendar_add_event_opened` - при открытии формы добавления
- `calendar_edit_event_opened` - при открытии формы редактирования (параметры: `event_id`)

## 2. Notifications

### 2.1. Цель и Контекст

**Бизнес-задача:** Централизованный экран уведомлений пользователя: системные уведомления, напоминания о событиях, обновления приложения. Категоризация уведомлений для удобной навигации.

**Место в сценарии:** Доступен из Home Screen (иконка уведомлений с badge) или через навигацию. Является центром всех уведомлений приложения.

**Ключевые функции:** Просмотр уведомлений, фильтрация по категориям, управление настройками уведомлений.

  - Действие: `viewModel.navigateBack()`
- Правая иконка: Отсутствует
- Отступы: Горизонтальные 20 points

**Компонент: SegmentControlUI**
- Тип: Сегментированный контрол
- Сегменты: `viewModel.categories`
  - "Все"
  - "Популярные"
  - "Новинки"
  - "Рекомендуемые"
- Привязка: `$viewModel.selectedCategory`
- Минимальная ширина сегмента: 100 points

## 3. Profile

## 4. Forgot Password

### 4.1. Цель и Контекст

**Бизнес-задача:** Восстановление пароля через отправку кода подтверждения на email. Первый шаг процесса восстановления доступа к аккаунту.

**Место в сценарии:** Отображается из Authorization (кнопка "Забыли пароль?"). После успешной отправки кода пользователь может вернуться на экран авторизации или продолжить процесс восстановления.

**Ключевые функции:** Ввод email, отправка кода восстановления, валидация email.

### 4.2. Элементы Интерфейса и Функциональность

- Отступы: Горизонтальные 20 points, верхний 50 points

**Компонент: ForgotPasswordContentView**

  - Компонент: `TextFieldUI`

  - Позиция: Справа от поля
  - Текст: "remember_password" ("Вспомнили пароль? Войти")

    - Загрузка: Показывает индикатор
  - Действие: `viewModel.sendResetCode()`
  - Высота: Минимум 60 points

**Компонент: ForgotPasswordFooter**

## 5. Verification

### 5.1. Цель и Контекст

**Бизнес-задача:** Подтверждение email адреса через ввод кода, отправленного на почту. Завершение процесса регистрации или восстановления пароля.

**Место в сценарии:** Отображается после регистрации (с email) или как часть процесса восстановления пароля. После успешной верификации пользователь получает доступ к приложению.

**Ключевые функции:** Ввод кода подтверждения, повторная отправка кода, автоматическая верификация при вводе полного кода.

### 5.2. Элементы Интерфейса и Функциональность

#### 5.2.1. Структура Экрана

**Компонент: VerificationHeader**
- Логотип: Изображение `logo`, размер 90x90 points
- Заголовок: "verification_title" ("Верификация")
- Описание: "verification_description" ("Мы отправили код подтверждения на")
- Email: Отображается синим цветом, semibold
- Отступы: Горизонтальные 30 points

**Компонент: VerificationContentView**
- Поле "Код подтверждения":
  - Заголовок: "verification_code_title" ("Код подтверждения")
  - Компонент: `OTPInputUI`
  - Привязка: `$viewModel.verificationCode`
  - Конфигурация: `OTPConfiguration(length: 6)`
  - Действия:
    - `onComplete`: Автоматическая верификация при вводе 6 цифр
    - `onCodeChanged`: Обновление кода
  - Ошибка: `viewModel.codeError` (отображается под полем)
- Кнопка "Подтвердить":
  - Компонент: `ButtonUI`
  - Стиль: Primary button, цвет indigo
  - Текст: "button_verify" (локализованный)
  - Состояния:
    - Неактивна: Если `isLoading` или `verificationCode.count != 6`
    - Загрузка: Показывает индикатор
  - Действие: `viewModel.verifyCode(code:)`
  - Высота: Минимум 60 points

**Компонент: VerificationFooter**
- Текст "Не получили код?":
  - Стиль: Обычный текст, серый цвет
- Кнопка "Отправить снова":
  - Текст: "resend_code" ("Отправить снова")
  - Стиль: Синий цвет, semibold
  - Действие: `viewModel.resendCode()`
  - Состояние: Неактивна во время загрузки или cooldown
- Таймер обратного отсчета:
  - Условие: `resendCooldown > 0`
  - Текст: "Отправить снова через [X] сек"
  - Стиль: Мелкий шрифт (caption), серый цвет

#### 5.2.2. Интерактивность

**Ввод кода:**
- Автоматический переход между полями
- Автоматическая верификация при вводе 6 цифр
- Очистка ошибки при изменении

**Тап на кнопку "Подтвердить":**
- Валидация кода (должен быть 6 цифр)
- Если валидно: Отправка запроса на сервер
- Если невалидно: Отображение ошибки

**Тап на "Отправить снова":**
- Отправка нового кода на email
- Запуск таймера обратного отсчета (60 секунд)
- Кнопка неактивна во время cooldown

#### 5.2.3. Валидация Данных

**Код подтверждения:**
- Длина: Ровно 6 цифр
- Формат: Только цифры
- Сообщение об ошибке: "Код должен содержать 6 цифр"

**Валидация на клиенте:**
- Проверка длины кода
- Проверка формата (только цифры)

**Валидация на сервере:**
- Проверка корректности кода
- Проверка срока действия кода
- Проверка соответствия кода email
