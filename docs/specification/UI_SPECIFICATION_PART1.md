## 1. Splash Screen

### 1.1. Цель и Контекст

**Бизнес-задача:** Первое впечатление пользователя при запуске приложения. Экран выполняет техническую инициализацию (проверка авторизации, загрузка конфигурации) и определяет следующий экран в flow приложения.

**Место в сценарии:** Самый первый экран, отображается при каждом запуске приложения. После завершения инициализации происходит автоматический переход на следующий экран согласно `AppFlowManager`.

**Продолжительность отображения:** Минимум 1-2 секунды (для восприятия бренда), максимум 5 секунд (технический таймаут).

### 1.2. Элементы Интерфейса и Функциональность

#### 1.2.1. Визуальные Элементы

**Логотип приложения:**
- Изображение: `logo` из Assets
- Размер: 90x90 points
- Позиция: Центр экрана (вертикально и горизонтально)
- Анимация: Плавное появление (fade-in) с масштабированием от 0.8 до 1.0
- Длительность анимации: 0.5 секунды

**Текст "Loading...":**
- Позиция: Под логотипом, отступ 20 points
- Шрифт: System font, regular, 16pt
- Цвет: Системный серый (secondary label color)
- Анимация: Постепенное появление букв (опционально, для улучшения UX)
- Условие отображения: Появляется через 0.3 секунды после начала загрузки

**Фоновый цвет:**
- Цвет: `Background` из темы приложения
- Полноэкранный фон без дополнительных элементов

#### 1.2.2. Интерактивность

**Отсутствие пользовательского взаимодействия:**
- Экран не реагирует на тапы или свайпы
- Нет кнопок для пропуска
- Автоматический переход после завершения инициализации

#### 1.2.3. Состояния Экрана

**Состояние: Инициализация**
- Логотип отображается с анимацией
- Текст "Loading..." появляется с задержкой
- Выполняются фоновые операции:
  - Проверка статуса авторизации (`SplashRepository.getIsAuthenticated()`)
  - Проверка завершения onboarding (`SettingsManager.hasCompletedOnboarding`)
  - Проверка активной подписки (`SettingsManager.hasActiveSubscription`)
  - Определение следующего маршрута (`AppFlowManager.determineNextScreen()`)

**Состояние: Завершение**
- После определения маршрута происходит плавный переход (fade-out)
- Длительность перехода: 0.3 секунды
- Переход на следующий экран без видимого "прыжка"

### 1.3. Техническая Реализация

#### 1.3.1. Сервисы и API

**Локальные проверки (без API вызовов):**
- `SplashRepository.getIsAuthenticated()` - проверка сохраненного токена
- `SettingsManager.hasCompletedOnboarding` - проверка флага первого запуска
- `SettingsManager.hasActiveSubscription` - проверка статуса подписки
- `AppFlowManager.determineNextScreen()` - логика определения маршрута

**Сценарии определения маршрута:**
- Первый запуск → `.onboarding`
- Не авторизован → `.auth`
- Нет подписки → `.subscription`
- Все условия выполнены → `.home`

#### 1.3.2. Навигация

**Автоматический переход:**
- После завершения инициализации вызывается `coordinator.navigateToRoute(nextRoute)`
- Переход происходит через `NavigationState`
- Анимация перехода: стандартная SwiftUI навигация

**Возможные следующие экраны:**
- `.onboarding` - первый запуск
- `.auth` - требуется авторизация
- `.subscription` - требуется подписка
- `.home` - главный экран

#### 1.3.3. Данные

**Данные, используемые на экране:**
- Логотип из Assets (статический ресурс)
- Состояние авторизации (локальное хранилище)
- Флаги onboarding и subscription (UserDefaults/Keychain)

**Данные, НЕ отображаемые:**
- Техническая информация о загрузке
- Ошибки инициализации (обрабатываются автоматически)

#### 1.3.4. Обработка Ошибок

**Сценарии ошибок:**
- Ошибка чтения локального хранилища → переход на `.auth` (безопасный fallback)
- Таймаут инициализации (>5 секунд) → переход на `.auth`
- Ошибки не отображаются пользователю, логируются через `Logger`

## 2. Onboarding

### 2.1. Цель и Контекст

**Бизнес-задача:** Знакомство новых пользователей с ключевыми возможностями приложения. Объяснение ценности платформы и мотивация к регистрации.

**Место в сценарии:** Отображается только при первом запуске приложения (после Splash Screen, если `hasCompletedOnboarding == false`). После завершения onboarding пользователь переходит к авторизации или подписке.

**Количество экранов:** 3 карточки с информацией о приложении.

### 2.2. Элементы Интерфейса и Функциональность

#### 2.2.1. Структура Экрана

**Компонент: OnboardCardListWidget**
- Тип: Карусель карточек (TabView в SwiftUI)
- Ориентация: Горизонтальная прокрутка
- Индикатор страниц: Точки внизу экрана (PageControl)
- Анимация перехода: Плавный swipe между карточками

#### 2.2.2. Карточки Onboarding

**Карточка 1: "Introduction to onboarding"**
- Изображение: `onboarding1` из Assets
- Заголовок: "Introduction to onboarding"
- Описание: "Learn how to create engaging onboarding screens using Swift ui"
- Позиция: Первая карточка (index 0)

**Карточка 2: "Building ui component"**
- Изображение: `onboarding2` из Assets
- Заголовок: "Building ui component"
- Описание: "Discover how to accept onboarding screens using Swift ui"
- Позиция: Вторая карточка (index 1)

**Карточка 3: "Adding interactivity"**
- Изображение: `onboarding3` из Assets
- Заголовок: "Adding interactivity"
- Описание: "Enhance your onboarding experience with animations and smooth"
- Позиция: Третья карточка (index 2)

**Структура каждой карточки:**
- Изображение: Занимает верхнюю часть (60% высоты)
- Заголовок: Крупный шрифт, жирный, центрирован
- Описание: Мелкий шрифт, центрирован, серый цвет
- Отступы: 20 points со всех сторон

#### 2.2.3. Элементы Управления

**Кнопка "Далее" (Next):**
- Позиция: Внизу карточки, центрирована
- Стиль: Primary button (индиго цвет)
- Текст: "Далее" или локализованный эквивалент
- Действие:
  - На карточках 1-2: Переход на следующую карточку
  - На карточке 3: Завершение onboarding и переход дальше

**Кнопка "Пропустить" (Skip):**
- Позиция: Верхний правый угол
- Стиль: Text button (текстовая ссылка)
- Текст: "Пропустить"
- Действие: Немедленное завершение onboarding (переход к следующему экрану)

**Индикатор страниц (Page Control):**
- Позиция: Внизу экрана, над кнопкой "Далее"
- Визуализация: 3 точки, активная точка выделена
- Интерактивность: Не интерактивен (только визуальный индикатор)

#### 2.2.4. Интерактивность

**Swipe жесты:**
- Горизонтальный swipe влево → следующая карточка
- Горизонтальный swipe вправо → предыдущая карточка
- Анимация: Плавный переход с эффектом "страницы"

**Тап на кнопку "Далее":**
- Анимация: Плавное увеличение текущей карточки (scale 1.0 → 1.05 → 1.0)
- Переход: Анимация swipe к следующей карточке
- На последней карточке: Завершение onboarding

**Тап на "Пропустить":**
- Немедленное завершение onboarding
- Сохранение флага `hasCompletedOnboarding = true`
- Переход на следующий экран

#### 2.2.5. Валидация

**Валидация не требуется:**
- Экран информационный, пользовательский ввод отсутствует
- Все действия являются навигационными

### 2.3. Техническая Реализация

#### 2.3.1. Сервисы и API

**API вызовы отсутствуют:**
- Данные карточек хранятся локально в `OnboardingViewModel`
- Используются только локальные ресурсы (изображения из Assets)

**Локальные операции:**
- Сохранение флага `SettingsManager.shared.hasCompletedOnboarding = true`
- Определение следующего маршрута через `AppFlowManager.determineAfterOnboarding()`

#### 2.3.2. Состояния Экрана

**Состояние: Отображение карточек**
- Текущая карточка: `currentTab` (0, 1, или 2)
- Анимация перехода: Плавная (withAnimation)
- Индикатор страниц: Обновляется синхронно с текущей карточкой

**Состояние: Завершение**
- Флаг onboarding сохраняется
- Определяется следующий маршрут
- Происходит переход на следующий экран

#### 2.3.3. Навигация

**После завершения onboarding:**
- Вызывается `AppFlowManager.determineAfterOnboarding()`
- Возможные маршруты:
  - `.subscription` - если требуется подписка (full flow)
  - `.auth` - если не авторизован
  - `.home` - если авторизован и есть подписка

**Метод перехода:**
- `coordinator.navigateToRoute(nextRoute)`
- Анимация: Стандартная SwiftUI навигация

#### 2.3.4. Данные

**Данные карточек:**
```swift
struct Onboarding {
    let image: String      // Имя изображения из Assets
    let title: String      // Заголовок карточки
    let description: String // Описание карточки
}
```

**Текущее состояние:**
- `currentTab: Int` - индекс текущей карточки (0-2)
- `onboardingList: [Onboarding]` - массив карточек

#### 2.3.5. Аналитика

**Отслеживаемые события:**
- `onboarding_tab_changed` - при смене карточки (параметры: `tab`)
- `onboarding_next` - при нажатии "Далее" (параметры: `current_tab`)
- `onboarding_skipped` - при нажатии "Пропустить" (параметры: `completed_tabs`)
- `onboarding_completed` - при завершении (параметры: `next_route`)
- `screen_view: Onboarding` - при появлении экрана

## 3. Authorization (Login)

### 3.1. Цель и Контекст

**Бизнес-задача:** Авторизация существующих пользователей в системе. Предоставление доступа к функционалу приложения после успешной аутентификации.

**Место в сценарии:** Отображается после Splash/Onboarding, если пользователь не авторизован. После успешной авторизации пользователь переходит на главный экран (Home).

**Альтернативные пути:**
- Регистрация нового пользователя (кнопка "Зарегистрироваться")
- Восстановление пароля (кнопка "Забыли пароль?")
- Социальная авторизация (Google, Apple)

### 3.2. Элементы Интерфейса и Функциональность

#### 3.2.1. Структура Экрана

**Компонент: Header**
- Логотип: Изображение `logo`, размер 90x90 points
- Заголовок: Локализованный текст "title" (название приложения)
- Описание: Локализованный текст "description" (краткое описание)
- Позиция: Верхняя часть экрана, центрировано
- Отступы: 50 points сверху, горизонтальные отступы

**Компонент: ContentView**
- Поля ввода: Email и Password
- Кнопка входа: Primary button
- Ссылки: "Забыли пароль?" и "Зарегистрироваться"
- Позиция: Центральная часть экрана

**Компонент: Footer**
- Разделитель: "or" с линиями по бокам
- Кнопки социальной авторизации: Google и Apple
- Лицензионное соглашение: Текст внизу
- Позиция: Нижняя часть экрана

#### 3.2.2. Поля Ввода

**Поле Email:**
- Тип: `TextFieldUI` с конфигурацией `.email`
- Иконка: Системная иконка "envelope"
- Placeholder: "Email address"
- Валидация:
  - Формат email (регулярное выражение)
  - Обязательное поле
- Ошибка: Отображается под полем красным цветом (`emailError`)
- Привязка: `@Published var email: String`
- Действие при изменении: `viewModel.inputEmain(email:)`

**Поле Password:**
- Тип: `TextFieldUI` с конфигурацией `.password`
- Иконка: Системная иконка "lock"
- Placeholder: "Password"
- Безопасность: Скрытие ввода (secure text field)
- Валидация:
  - Минимальная длина (определяется на бэкенде)
  - Обязательное поле
- Ошибка: Отображается под полем красным цветом (`passwordError`)
- Привязка: `@Published var password: String`
- Действие при изменении: `viewModel.inputPassword(password:)`

#### 3.2.3. Кнопки и Ссылки

**Кнопка "Войти" (Login):**
- Стиль: Primary button, цвет индиго
- Текст: Локализованный "button_login"
- Состояния:
  - Активна: Когда поля заполнены и валидны
  - Неактивна (`isDisabled`): Во время загрузки (`isLoading`)
  - Загрузка: Показывает индикатор загрузки вместо текста
- Действие: `viewModel.login(email:password:)`
- Высота: Минимум 60 points

**Ссылка "Забыли пароль?":**
- Позиция: Справа от полей ввода
- Стиль: Текстовая ссылка, синий цвет
- Действие: `viewModel.navigateToForgotPassword()`
- Навигация: Переход на экран `.forgotPassword`

**Ссылка "Зарегистрироваться":**
- Позиция: Под кнопкой "Войти"
- Стиль: Текстовая ссылка, синий цвет
- Текст: "Уже есть аккаунт? Войти" (локализованный)
- Действие: `viewModel.navigateToRegistration()`
- Навигация: Переход на экран `.registration`

#### 3.2.4. Социальная Авторизация

**Разделитель "or":**
- Компонент: `LabelledDivider`
- Текст: "or" (или локализованный эквивалент)
- Стиль: Горизонтальная линия с текстом по центру

**Кнопка "Войти через Google":**
- Иконка: `google_logo` из Assets
- Стиль: Bordered button (рамка)
- Текст: Локализованный "button_signin_google"
- Действие: `viewModel.signInWithGoogle(token:)`
- Состояние: Неактивна во время загрузки

**Кнопка "Войти через Apple":**
- Иконка: `apple_logo` из Assets
- Стиль: Bordered button (рамка)
- Текст: Локализованный "button_signin_apple"
- Действие: `viewModel.signInWithApple(token:)`
- Состояние: Неактивна во время загрузки

#### 3.2.5. Лицензионное Соглашение

**Текст соглашения:**
- Позиция: В самом низу экрана
- Стиль: Мелкий шрифт (caption2)
- Содержание:
  - Локализованный текст "licence_lable"
  - Локализованный текст "licence_title"
- Выравнивание: По центру, многострочный текст

#### 3.2.6. Интерактивность

**Ввод данных:**
- Реакция на изменение: Валидация в реальном времени
- Ошибки: Отображаются сразу после потери фокуса или при попытке отправки
- Автозаполнение: Поддержка системного автозаполнения паролей (iOS Keychain)

**Тап на кнопку "Войти":**
- Валидация всех полей
- Если валидно: Отправка запроса на сервер
- Если невалидно: Отображение ошибок под полями

**Тап на социальные кнопки:**
- Запуск OAuth flow (Google/Apple)
- Получение токена от провайдера
- Отправка токена на бэкенд

#### 3.2.7. Валидация Данных

**Email:**
- Формат: Должен соответствовать стандарту email (regex)
- Обязательность: Поле не может быть пустым
- Сообщение об ошибке: "Введите корректный email"

**Password:**
- Минимальная длина: Определяется бэкендом (обычно 6-8 символов)
- Обязательность: Поле не может быть пустым
- Сообщение об ошибке: "Пароль слишком короткий" или от сервера

**Валидация на клиенте:**
- Проверка формата email (regex)
- Проверка минимальной длины пароля
- Проверка на пустые поля

**Валидация на сервере:**
- Проверка существования пользователя
- Проверка корректности пароля
- Проверка статуса аккаунта (активен/заблокирован)

### 3.3. Техническая Реализация

#### 3.3.1. Сервисы и API

**API Endpoint: POST /auth/login**
- Метод: `POST`
- Путь: `/auth/login`
- Требует авторизации: Нет (`requiresAuth: false`)
- Тело запроса:
```json
{
  "email": "string",
  "password": "string"
}
```

**Ответ при успехе (200 OK):**
```json
{
  "accessToken": "string",
  "refreshToken": "string"
}
```

**Ответ при ошибке (400/401):**
```json
{
  "error": "string",
  "message": "string"
}
```

**Use Case: LoginUseCase**
- Входные данные: `LoginRequest(email: String, password: String)`
- Выходные данные: `NetworkResult<AuthTokens>`
- Действия:
  1. Создание `NetworkRequest` с телом запроса
  2. Вызов `NetworkService.request()`
  3. Обработка ответа
  4. Сохранение токенов в `AuthRepository`
  5. Установка флага авторизации

**Социальная авторизация:**
- **Google:** `POST /auth/google` с токеном от Google
- **Apple:** `POST /auth/apple` с токеном от Apple
- Use Cases: `SignInWithGoogleUseCase`, `SignInWithAppleUseCase`

#### 3.3.2. Состояния Экрана

**Состояние: Инициализация**
- Поля пустые или с тестовыми значениями (DEBUG)
- Кнопки активны
- Ошибок нет

**Состояние: Загрузка (`isLoading = true`)**
- Кнопка "Войти" показывает индикатор загрузки
- Все кнопки неактивны (`isDisabled = true`)
- Поля ввода заблокированы
- Анимация: Spinner в кнопке

**Состояние: Успех**
- Токены сохранены в `AuthRepository`
- Флаг `isAuthenticated = true`
- Переход на главный экран (`.home`)

**Состояние: Ошибка**
- Отображение `Alert` с сообщением об ошибке
- Ошибки валидации отображаются под полями
- Кнопки снова активны
- Пользователь может повторить попытку

**Состояние: Пустое**
- Не применимо (экран всегда имеет контент)

#### 3.3.3. Навигация

**Исходящие переходы:**
- Успешная авторизация → `.home` (через `coordinator.completeAuth()`)
- Кнопка "Зарегистрироваться" → `.registration`
- Кнопка "Забыли пароль?" → `.forgotPassword`

**Входящие переходы:**
- Из Splash/Onboarding (если не авторизован)
- Из Registration (кнопка "Уже есть аккаунт?")

**Методы навигации:**
- `coordinator.completeAuth()` - после успешной авторизации
- `coordinator.showRegistration()` - переход на регистрацию
- `coordinator.showForgotPassword()` - переход на восстановление пароля

#### 3.3.4. Данные

**Входные данные (от пользователя):**
- `email: String` - email пользователя
- `password: String` - пароль пользователя

**Выходные данные (от сервера):**
- `accessToken: String` - токен доступа (JWT)
- `refreshToken: String` - токен обновления

**Локальное хранение:**
- Токены сохраняются в `KeychainService` (безопасное хранилище)
- Флаг авторизации: `AuthRepository.setIsAuthenticated(true)`

**Модели данных:**
```swift
struct LoginRequest {
    let email: String
    let password: String
}

struct AuthTokens {
    let accessToken: String
    let refreshToken: String
}
```

#### 3.3.5. Обработка Ошибок

**Типы ошибок:**
- **Валидация (400):** Неверный формат email или пароль
- **Неавторизован (401):** Неверный email или пароль
- **Сервер (500):** Внутренняя ошибка сервера
- **Сеть:** Отсутствие интернета, таймаут

**Отображение ошибок:**
- Ошибки валидации: Под соответствующими полями ввода
- Ошибки сервера: Alert с сообщением
- Ошибки сети: Alert с предложением проверить подключение

**Логирование:**
- Все ошибки логируются через `Logger.log(.error, ...)`
- Контекст: `["action": "login", "email": email]`

#### 3.3.6. Аналитика

**Отслеживаемые события:**
- `screen_view: Authorization` - при появлении экрана
- `user_logged_in` - при успешной авторизации (параметры: `method: "email"|"google"|"apple"`)
- `navigate_to_registration` - при переходе на регистрацию
- `navigate_to_forgot_password` - при переходе на восстановление пароля

## 5. Subscription

**Бизнес-задача:** Предоставление пользователю возможности оформить премиум-подписку для доступа к расширенному функционалу приложения. Монетизация платформы через модель подписок.

**Место в сценарии:** Отображается после Onboarding (в full flow) или после Authorization, если у пользователя нет активной подписки. После успешной покупки пользователь получает доступ к главному экрану.

**Модель подписки:** Премиум-подписка с расширенными возможностями (облачное хранилище, эксклюзивный контент, аналитика).

#### 5.2.1. Структура Экрана
